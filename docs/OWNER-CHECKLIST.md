**Как пользоваться:** идти сверху вниз, галочка ставится только когда получилось; если команда выдаёт ошибку — остановиться и прислать мне вывод (без паролей и секретов), а не «чинить наугад».
**Куда смотреть подробности:** при каждом пункте есть ссылка на подробную инструкцию. Записка короткая, подробности там.

## 1. Репетиция на вашем ПК (Этап 1: Stack Ready gate)

Делается один вечер, на Windows 10/11. Подробная инструкция по каждому шагу — [`PLATFORM-REHEARSAL.md`](PLATFORM-REHEARSAL.md) (разделы A–F).

- [ ] **1.1. Поставить базу.** Docker Desktop (с WSL2), Node.js версии 22.16 или новее, выполнить `npm ci` в корне репозитория. Проверка: `node --version` печатает `v22.x`. → Подробно: PLATFORM-REHEARSAL.md, раздел A.
- [ ] **1.2. Поднять локальный «полигон».** Команды `npm run platform:local:init` (один раз), `up`, `migrate`, `status`. Успех: `http://127.0.0.1:4400/api/v2/health` отвечает `ready`, порты видны только на этом ПК (127.0.0.1). → Подробно: PLATFORM-REHEARSAL.md, раздел A.
- [ ] **1.3. Отрепетировать «сломать и откатить».** Сделать резервную копию, восстановить из неё, сверить, что всё совпало, повторить откат на автосохранённую «спасательную» копию. Успех: команды не падают, восстановление успешно, вы записали, сколько это заняло по времени. → Подробно: PLATFORM-REHEARSAL.md, раздел B; как устроен backup/restore вообще: [`PLATFORM-OPERATIONS.md`](PLATFORM-OPERATIONS.md), раздел 2 и [`BETA-WINDOWS-LOCAL.md`](BETA-WINDOWS-LOCAL.md).
- [ ] **1.4. Проверить Redis «вживую».** Убедиться, что CI-прогон зелёный, прогнать тесты ограничения запросов против живого Redis (одна команда через одноразовый контейнер) и взглянуть на ключи — там должны быть только хэши, не ваши IP/email. → Подробно: PLATFORM-REHEARSAL.md, раздел C.
- [ ] **1.5. Принять решение по лимитам.** Ответить на 4 вопроса: годятся ли лимиты для закрытой альфы (10 артистов + 50 слушателей), допустим ли двойной всплеск на границе минутного окна, что делать при недоступном Redis (ответ уже заложен: 503, публику не пускаем), выносить ли лимиты в настройки. Решение записать мне — код не трогаем до вашего решения. → Подробно: PLATFORM-REHEARSAL.md, раздел C3.
- [ ] **1.6. Включить наблюдаемость.** Локально: `/metrics` отдаёт метрики с токеном, 404 без него. Для «продакшена» (позже): кто хранит токен, какие сроки хранения у логов и метрик, кому приходят алерты, и один учебный «инцидент» (остановили API → алерт сработал → подняли обратно). Метки-пороги уже предложены: [`../deploy/observability/prometheus-alerts.example.yml`](../deploy/observability/prometheus-alerts.example.yml). → Подробно: PLATFORM-REHEARSAL.md, раздел D.
- [ ] **1.7. (По желанию) Отрепетировать импортёр.** Только если хотите перенести старые личные треки в v2: свежий проверенный архив → dry-run → apply на **одноразовом** контуре → сверка отчёта. Ничего не публикуется; каждый трек останется приватным и в карантине. Если перенос не нужен — напишите мне решение «не импортируем». → Подробно: PLATFORM-REHEARSAL.md, раздел E; правила переноса данных: PLATFORM-OPERATIONS.md, раздел 3.
- [ ] **1.8. Подписать таблицу F.** Заполнить дату и результат по каждой строке таблицы в конце PLATFORM-REHEARSAL.md и сказать мне «принимаю Stack Ready» (или прислать, что не сошлось). → Подробно: PLATFORM-REHEARSAL.md, раздел F.

**Зачем это нужно:** без подписи владельца gate считается непринятым; я не имею права отметить его закрытым за вас, и до подписи никакого запуска наружу нет.

## 3. Внешние гейты, которые нельзя «дожать кодом»

Эти пункты держатся на людях и документах, не на сервере; техника их не заменяет:

- [ ] **3.1. Юрист.** Получить внешнее заключение по правам на пользовательскую музыку (оферта, notice-and-takedown, повторные нарушители, персональные данные). Материалы для консультации готовы: [`legal/CONSULTATION-BRIEF.md`](legal/CONSULTATION-BRIEF.md).
- [ ] **3.2. Решение по репликации контента (ADR-0015)** — остаётся открытым; без него публичная раздача/peer-seeding заблокированы. Документ: [`adr/0015-rights-aware-replication.md`](adr/0015-rights-aware-replication.md).
- [ ] **3.3. Бета.** Фактически согласовать 10 артистов + 50 слушателей (это 0/0). Шаблоны согласия и формы обратной связи готовы: [`BETA-PLAN.md`](BETA-PLAN.md), [`BETA-CONSENT-TEMPLATE.md`](BETA-CONSENT-TEMPLATE.md), [`BETA-FEEDBACK-FORM.md`](BETA-FEEDBACK-FORM.md).
- [ ] **3.4. Продакшен-решения.** Регион, бюджет и конкретные провайдеры: хранилище (S3-альтернатива), fingerprint-сервис, TTS-голос (OpenAI/ElevenLabs/локальная модель), домен и TLS. До выбора работаем на локальных заглушках — это осознанно.

## 4. Чего делать не нужно (стоп-краны)

- Не регистрировать внешних участников и не открывать регистрацию/загрузки на сервере.
- Ничего не публиковать в интернет: ни треки, ни API, ни `/metrics`; токен метрик — только в заголовке запроса, никогда в URL и никогда не коммитить его в Git.
- Не коммитить `backups/`, `.env*`, архивы бэкапов.
- Не трогать `apps/mobile/vision-release.p12` (ключ подписи Android): не удалять, не ротировать без отдельного плана выпуска.
- Не мержить `main` и не нажимать «релиз» до полной приёмки gate и юр. решений.
- Не отправлять мне секреты (пароли, токены, архивы с личной музыкой) — только факты и выводы команд.

## 5. Если что-то падает

Присылайте: номер шага (например «1.3»), команду, которую вводили, и полный вывод (без паролей). Я скажу, что исправить, или сам исправлю в коде. Не пробуйте «обойти» ошибку повторными запусками разрушительных команд (`--confirm` у restore) — сначала спросите.
