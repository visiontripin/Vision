# Улучшения, оптимизации и дорожная карта Vision Audio

Основано на разборе SoundCloud (`docs/research/SOUNDCLOUD-TEARDOWN.md`) и текущем состоянии
репозитория. Документ отвечает на три вопроса: **что улучшить**, **что оптимизировать**,
**в каком порядке делать**. Дорожная карта ниже расширяет и заменяет `docs/ROADMAP.md`
(старый файл остаётся как история этапов 0–4).

---

## 0. Где мы сейчас (честная диагностика)

_Обновлено в v0.19.0: прежняя версия этого раздела описывала состояние до v0.6 и
вводила в заблуждение — половина «главных рисков» уже закрыта._

**Есть и работает**
- Web-MVP: библиотека, FTS-поиск, drag&drop загрузка с волной в браузере, плеер (очередь,
  shuffle, повтор, восстановление сессии, Media Session, полный экран с волной-скраббером),
  плейлисты, лайки, статистика, история, офлайн-копии.
- API на Node 22 + SQLite: HMAC-токены, подписанные медиа-ссылки, Range/206, HLS и
  транскодинг opus/aac с нормализацией −14 LUFS, magic-bytes, rate limit, метрики Prometheus,
  миграции (`schema_version`, 10 штук), дедупликация по SHA-256, теги из файлов и обложки.
- Приватные ссылки с TTL/отзывом/лимитом открытий, таймкод-комментарии, oEmbed и
  встраиваемый виджет, журнал действий.
- Приложения: Android APK (Expo, v0.4.0), настольная сборка Tauri (`.deb`/`.AppImage`),
  «Vision Server» для Windows/Android (панель запуска и администрирования), PWA с офлайн-оболочкой.
- Общий клиент `@vision/shared` для web/mobile/desktop; 99 контрактных + 90 клиентских + 8 скриптовых тестов;
  CI: тесты, типы, сборки веба, панели и обеих стор-сборок.

**Чего нет (и это оставшиеся риски)**
| Пробел | Почему важно | Где болит |
|--------|--------------|-----------|
| Нет e2e-тестов браузера (Playwright) | регрессии в UI ловятся руками | `apps/web` |
| Нет локального кэша библиотеки на десктопе (I5) | библиотека пустая без сети | `apps/desktop` |
| Загрузка с телефона не сделана (H4) | NTFS/Telegram-файл с телефона не залить | `apps/mobile` |
| Нет gapless/кроссфейда (A5/A6) | пауза между треками слышна | `apps/web/src/state/player.tsx` |
| Нет умных подборок и автотегов (J1–J3) | ручная сортировка библиотеки | Фаза 5 |
| Нет квот и мультипользовательности | продукт личный по замыслу | `docs/PRODUCT.md` §6.1 |
| Нет crash-репортинга мобильного | о падении узнаём со слов | `apps/mobile` |

## 2. Оптимизации (технические, с ожидаемым эффектом)

| # | Что | Как | Ожидаемый эффект |
|---|-----|-----|------------------|
| O1 | Поиск | FTS5-таблица (`tracks_fts`) + триггеры, `MATCH` вместо `LIKE` | поиск по 100k треков < 20 мс вместо O(n) на клиенте |
| O2 | Список | виртуализация (react-window) + серверная пагинация по 100 | 10k строк без фризов, память −80% |
| O3 | Первая отрисовка | `React.lazy` для модалки загрузки и статистики; preload шрифтов не нужен; бандл < 250 КБ gzip | TTI < 1.5 с на 4G |
| O4 | Стриминг | `Cache-Control: private, max-age`, `ETag`, HTTP/1.1 keep-alive → HTTP/2 на прокси | повторные прослушивания без трафика |
| O5 | Prefetch | `fetch(streamUrl, {headers:{Range:'bytes=0-262143'}})` для следующего трека | пауза между треками ≈ 0 |
| O6 | SQLite | `PRAGMA journal_mode=WAL`, `synchronous=NORMAL`, батч-вставки в транзакции | запись в 5–10 раз быстрее |
| O7 | Волна | 180 → 320 пиков, сглаживание по 3, отрисовка через `Path2D` и один `fill` | меньше CPU при 60 fps |
| O8 | Обложки | ресайз при загрузке (2 размера: 128 и 640), WebP, `srcset` | −60% трафика на список |
| O9 | Локальный режим | хранить Blob в отдельном store, `getAllKeys` + ленивое создание object URL | не держим все аудио в памяти |
| O10 | API | сжатие ответов (gzip/brotli) для JSON > 1 КБ | −70% трафика списков |
| O11 | БД | индексы `tracks(created_at)`, `(liked)`, `playlist_tracks(playlist_id, position)` — уже есть; добавить `(genre)`, `(artist)` | фильтры без сканов |
| O12 | Загрузка | потоковая запись + `rename` (есть); добавить ограничение параллелизма на клиенте (2 файла) | стабильность на слабом канале |
| O13 | Мониторинг | `/metrics` + `prom-client`-совместимый формат, health с проверкой диска | MTTR с часов до минут |
| O14 | Кэш CDN | `stale-while-revalidate` для обложек и сегментов | мгновенная загрузка UI |

### Фаза 1 — «Прод-готовность веба» ✅ (v0.2.0 → v0.3.0)
**Цель:** личной библиотекой можно пользоваться каждый день, ничего не теряется.

- [x] FTS5-поиск, пагинация, сортировки (C1, C8, O1) — `002-fulltext-search`,
      `GET /api/tracks?q=&sort=&limit=&offset=` + `X-Total-Count`; веб-клиент
      ищет на сервере с дебаунсом и показывает общее число результатов.
      Список виртуализирован без зависимостей: окно ±8 строк, реальная высота
      строки измеряется через `getBoundingClientRect`, `aria-posinset/aria-setsize`
      сохраняют доступность (v0.3.0).
- [x] ID3/FLAC-теги и обложки при загрузке (C2, C3, O8) — собственный парсер
      без зависимостей, обложка ≤ 5 МБ, в UI рисуется из `/cover`.
- [x] Дедупликация по SHA-256 (C4) — `409 duplicate` + `existing`.
- [x] Подписанные URL для `/stream` и `/cover` (G1) — HMAC-SHA256, TTL 30 мин
      (`MEDIA_URL_TTL_MS`), `?token=` удалён, `timingSafeEqual`.
- [x] Миграции БД + `schema_version` (G2) — 4 миграции, статус в `/api/health`.
- [x] Бэкапы по cron и проверка восстановления (G8, D5) — `scripts/backup.sh`
      (WAL-safe, media + covers), процедура проверки в `docs/RUNBOOK.md` §4.
      Автоматического cron-примера в репозитории нет — это строчка в crontab владельца.
- [x] `/metrics`, структурные логи, алерты на диск и 5xx (G5, G6) — Prometheus-текст,
      JSON-логи с `X-Request-Id`, пороги алертов в RUNBOOK §5.
- [x] CSP/HSTS/Referrer-Policy, лимиты тела на всех маршрутах (G7) — заголовки на
      каждом ответе, CSP на HTML, `413` при превышении лимита.
- [x] «Продолжить слушать» + история (B1, D2) — `/listen`, `/api/history`,
      блок карточек с прогрессом и запуском с сохранённой позиции.

- [x] `/api/v1` + OpenAPI 3.1 (v0.3.0) — `GET /api/v1/openapi.json`, схема
      генерируется из `services/api/src/openapi.js`; `/api/*` остался алиасом.

**Остаток Фазы 1:** Lighthouse-прогон на реальном профиле (нужен браузер)

**KPI:** TTFB < 300 мс, поиск p95 < 100 мс, 0 потерянных файлов за месяц.

### Фаза 2 — «Аудио 2.0» (3–4 недели) · P0–P1
**Цель:** звук как у взрослого сервиса: лёгкий, быстрый, ровный по громкости.

## 6. Метрики продукта (что мерить)

| Метрика | Цель | Как мерить |
|---------|------|-----------|
| Время до первого звука | < 1.5 с | Lighthouse + RUM (PerformanceObserver) |
| Seek p95 | < 150 мс | замер `seeking → playing` |
| Buffer ratio | < 0.5% | `waiting` события / время |
| Успешность загрузок | > 99% | лог API + клиента |
| Поиск p95 | < 100 мс | лог FTS-запроса |
| Crash-free (mobile) | > 99.5% | Sentry/Crashlytics |
| Восстановление бэкапа | 100% | ежемесячный чек-лист |
| Диск | < 80% | `/metrics` + алерт |

## 7. Риски и ответы

| Риск | Ответ |
|------|-------|
| ffmpeg усложняет деплой | отдельный воркер-контейнер, очередь на SQLite/Kafka-lite; фолбэк — отдавать оригинал |
| HLS ломает простой `<audio>` | сначала opus + progressive; HLS за фиче-флагом |
| Рост библиотеки | дедупликация, лимит на размер, S3/MinIO как второй уровень |
| iOS background audio | dev-build + `UIBackgroundModes`, тест на реальном устройстве |
| Tauri собирается только на целевой ОС | CI-матрица Windows/Linux, подпись отдельным шагом |
| Public links = утечка | TTL + отзыв + отдельный токен, не сессионный |
| Scope creep в соцсеть | non-goals: репосты, подписки, публичный каталог |
| Один сервер = одна точка отказа | бэкапы, health, rollback, позже — реплика чтения |

## 8. Non-goals (держим фокус)

- Публичный каталог и поиск по чужим трекам.
- Соцсеть: репосты, подписки, лента, рекомендации «на весь мир».
- Монетизация, реклама, лейблы, copyright-модерация.
- Мультитенантность и тарифы (пока продукт личный).
- Живые трансляции, DAW/редактор аудио, чат.
