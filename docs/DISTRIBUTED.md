# Распределённое хранение: трекер и сиды

Исходная задача: **серверного хранилища нет**. Файлы живут на устройствах — у того,
кто их загрузил, и у тех, кто их слушает. Ответ на вопрос «сделать как в торрент-
трекерах» — «да, но без битфилдов и WebRTC»: транспорт — обычный HTTPS с
подписанными ссылками, а «рой» строится на реестре реплик.

**Статус v0.9.0:** этапы 1–2 сделаны (реестр, контент-адресация, раздача с узлов,
метаданные без файла, репликация с проверкой SHA-256). Этапы 3–4 — частично/позже.

## Как это работает

```
                    ┌──────────────────────────────┐
   метаданные  →    │  сервер-трекер (SQLite)      │  ← маленький, без аудио
   heartbeat   →    │  tracks / blobs / blob_seeds │
                    └──────────────┬───────────────┘
                                   │ «где лежит блоб X» + подписанные ссылки
        ┌──────────────────────────┼──────────────────────────┐
        ↓                          ↓                          ↓
  Termux (origin)            десктоп (node)              телефон (mobile)
  GET /seed/<hash>           GET /seed/<hash>            только реестр:
  Range, подпись             Range, подпись              «копия есть», не раздаёт
        │                          │                          │
        └──────── клиент качает с первого живого сида ────────┘
                  SHA-256 ✓ → копия у себя → стал репликой
```

- **Блоб** — содержимое, адрес = `sha256` файла. Один и тот же файл на трёх
  устройствах — один блоб и три сида.
- **Сид** — устройство с heartbeat (по умолчанию 3 минуты, обновление раз в минуту).
  Виды: `origin` (узел, где файл загрузили), `node` (Termux/ПК с файлом),
  `desktop`, `mobile` и `browser` — последние два раздавать не умеют, это «реплики».
- **Реплика** (`mobile`/`browser`) живёт в реестре 30 дней: «у меня есть копия».
  Скачать с неё нельзя — у браузера и телефона нет входящего HTTP-сервера.
- **Скачивание** — `GET /api/tracks/:id/download`: 302 на локальный `/seed/<hash>`
  или на первое живое устройство, 409 `no_source`, если файла нет ни у кого.
- **Целостность** — подпись HMAC в ссылке + сверка `sha256` после скачивания.
  Не совпало — копия удаляется, сид помечается ошибкой в логе.

### Модель данных (миграция `007-blobs`)

```sql
blobs       (hash PK, bytes, mime, created_at)
blob_seeds  (hash, device_id, kind, base_url, servable, online_at, PK(hash, device_id))
```

`tracks.checksum` ссылается на `blobs.hash` — дедупликация и адресация контента уже
были, миграция только добавила реестр и заполнила его из существующих треков.

### API

| Метод | Что делает |
| --- | --- |
| `POST /api/blobs` | объявить блоб (`hash`, `bytes`, `mime`), опционально сразу с сидом |
| `GET /api/blobs/:hash` | размер, mime, живые сиды, локальная копия |
| `GET /api/blobs/:hash/seeds` | сиды с подписанными ссылками `/seed/<hash>?exp&sig` |
| `POST /api/blobs/:hash/seed` | heartbeat устройства: `{ deviceId, kind, baseUrl }` |
| `DELETE /api/blobs/:hash/seed?deviceId=` | убрать устройство из реестра |
| `POST /api/blobs/:hash/replicate` | забрать файл с живого сида к себе (с проверкой хеша) |
| `GET /api/tracks/:id/download` | 302 на сид / 409 `no_source`; `?json=1` — адрес и список |
| `GET /api/seeds` | сводка трекера: блобы, сиды, реплики, треки без источника |
| `GET /seed/:hash?exp&sig` | отдача файла этим устройством (Range, ETag, HEAD) |

Треки в выдаче (`/api/tracks`, `/api/tracks/:id`, плейлисты, история, `/api/media`)
получают поля `checksum`, `sources` и `available`:

```json
"sources": { "hash": "a2c9…", "local": false, "servable": 1,
             "replicas": 2, "devices": 3, "kinds": { "node": 1, "browser": 2 } },
"available": true
```

### Режим «только метаданные»

`STORAGE_MODE=metadata` — узел принимает `POST /api/tracks` с JSON:

```json
{ "hash": "sha256 файла", "bytes": 7340032, "mime": "audio/mpeg",
  "title": "…", "artist": "…", "duration": 214, "peaks": [0.1, …],
  "deviceId": "laptop", "kind": "desktop", "baseUrl": "http://192.168.1.20:4000" }
```

Файл остаётся у загрузившего, сервер хранит метаданные и адрес сида. Обычный режим
(`STORAGE_MODE=local`, по умолчанию) по-прежнему принимает аудио потоком и сам
становится `origin`-сидом.

### Настройки

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `STORAGE_MODE` | `local` | `metadata` — не хранить аудио, только адреса |
| `SEED_ENABLED` | `1` | `0` — узел ничего не раздаёт (`/seed` → 403) |
| `SEED_DIR` | `<DATA_DIR>/seed` | каталог раздаваемых блобов `<hash>.<ext>` |
| `DEVICE_ID` | `origin` | имя устройства в реестре (`termux`, `laptop`, …) |
| `PUBLIC_URL` | — | адрес узла для других устройств (Tailscale/туннель) |
| `SEED_TTL_MS` | `180000` | сколько живёт heartbeat раздающего сида |
| `REPLICA_TTL_MS` | `30 дней` | сколько живёт запись о копии без раздачи |
| `EXTRA_ORIGINS` | — | через запятую: адреса соседних узлов для CSP (`media-src`) |

## Два узла за пять минут

```bash
# узел A (Termux/ПК): загружает файлы и раздаёт их
DATA_DIR=~/vision-a DEVICE_ID=node-a PUBLIC_URL=http://192.168.1.10:4000 npm start

# узел B: только метаданные, качает с A
DATA_DIR=~/vision-b DEVICE_ID=node-b STORAGE_MODE=metadata npm start
```

1. Загрузите трек на узле A → в `/api/seeds` появится блоб и сид `node-a`.
2. На узле B объявите трек: `POST /api/tracks` с JSON (см. выше), `baseUrl` = A.
3. `GET /api/tracks/<id>/download` на B → 302 на `http://192.168.1.10:4000/seed/…`.
4. `POST /api/blobs/<hash>/replicate` на B → файл скачан, хеш сверен, B раздаёт сам.
5. Выключите A: если B успел реплицировать — трек продолжает играть.

Проверка одной командой: `curl -s localhost:4000/api/health | jq .tracker`
(`blobs`, `seeds`, `servableBlobs`, `noSource`).

## Что даёт клиентам

- **Веб**: значок «нет источника» у трека, который сейчас не у кого скачать;
  «N» — сколько устройств держат файл; скачивание уходит на первый живой сид.
  Офлайн-копия автоматически объявляется репликой (`kind: browser`).
- **Телефон**: скачанная копия объявляется репликой (`kind: mobile`), при удалении —
  снимается. Плеер получает ссылку на сид тем же `/api/media`.
- **Отказ от трека**: `available: false` → кнопка воспроизведения показывает
  «Ни одно устройство сейчас не раздаёт этот файл» вместо ошибки сети.

## Почему не WebRTC/WebTorrent

1. Браузер не может отдавать файл по HTTP — только через WebRTC data channels.
2. WebRTC требует signalling, STUN и при CGNAT/симметричном NAT — TURN-релей, то есть
   трафик сервера и ежемесячный счёт. «Без серверного хранилища» превращается в
   «серверный трафик».
3. Сидирование из вкладки работает, только пока вкладка открыта; на телефоне ОС
   убивает фоновые процессы.
4. Битфилд и integrity пришлось бы писать самим (или тащить WebTorrent ~200–400 КБ).

Поэтому транспорт — HTTPS с подписанными ссылками (уже работает), а «рой» — реестр
реплик. WebRTC остаётся опцией, если окажется, что HTTPS-сидов регулярно не хватает.

## Что это меняет для Termux

Сервер остаётся, но перестаёт быть хранилищем: диск нужен под SQLite и кэш вариантов.
Файлы лежат в `~/.vision-seed/` (или в медиа-каталоге origin) и раздаются тем же HTTP-
слоем — отдельный протокол не нужен. `scripts/termux-setup.sh` уже прописывает
`DEVICE_ID=termux` и `SEED_ENABLED=1` в автозапуск.
