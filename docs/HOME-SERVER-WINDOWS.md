# Vision Server для Windows — архивный статус и критерии проверки

> **Не инструкция к установке.** В этой ветке нет проверенного Windows-релиза и
> подтверждённой установки. Не скачивайте `releases/latest` в поиске этого продукта:
> публикация workflow отключена, пригодного installer-артефакта не заявлено.
>
> Владелец выбрал v2-платформу и Windows для локального beta-prep. Это legacy
> Vision Server/SQLite-эксперимент, он не запускает v2 API и не подходит для этого
> сценария. Локальный backend smoke описан отдельно в
> [`BETA-WINDOWS-LOCAL.md`](BETA-WINDOWS-LOCAL.md); он использует Docker Compose,
> а не Windows-службу, и пока не является сайтом или бетой.

## Незакрытое решение владельца

Владелец ранее явно потребовал отдельный Windows Vision Server как собственную службу
с автозапуском и администраторским установщиком. В рамках Ф0.4 одновременно включена
временная заморозка console/desktop workflow до PMF (ADR-0016). Это противоречие
**не разрешено**: заморозка автоматических сборок не отменяет требование и не означает,
что продукт реализован или поставлен. Нужен отдельный выбор владельца — оставить
требование и согласовать исключение/план проверки либо явно пересмотреть его. До этого
не помечать Windows Server как shipped, tested или cancelled.

## Сохранённый инженерный набросок

В `apps/console` и `scripts/` сохранён неподтверждённый эксперимент: NSIS per-machine
установщик, bundled Node/API/FFmpeg, WinSW-служба `VisionServer`, данные в
`%ProgramData%`, настройка порта и первичная установка пароля владельца через loopback.
Это **намеренная архитектура кода**, а не доказательство, что ресурсы собираются,
служба устанавливается корректно или безопасно работает на Windows.

Workflow `.github/workflows/console.yml` только вручную запускает audit при явном
`validate: true`; по умолчанию он выводит статус. Успешный Linux/typecheck или наличие
NSIS hooks не заменяют реальный Windows build/install/runtime-тест. Автоматической
публикации релиза нет.

## Критерии до любого использования или релиза

После решения владельца потребуется отдельное разрешение на ручной workflow и review
результатов, затем проверка на чистой Windows 10/11 x64-машине как минимум:

1. NSIS-установщик запрашивает UAC/admin-права; файлы, ACL и удаление соответствуют
   per-machine установке.
2. Служба `VisionServer` регистрируется с автоматическим запуском, корректно стартует
   после перезагрузки, принимает stop/start через SCM и завершает процессы без потери
   данных.
3. Упакованные Node, API и FFmpeg реально запускаются; health, миграции и аудио-
   транскодирование проходят на Windows.
4. Первичная настройка пароля доступна только локально, пароль не хранится открыто,
   удалённый доступ к API проходит отдельную аутентификацию.
5. Данные/бэкапы сохраняются при обновлении и удалении, поведение firewall/портов
   понятно владельцу, логи не раскрывают секреты.
6. Инструкция и release checks обновлены только после полного прогона; неподписанный
   installer и ограничения поддержки явно указаны.
