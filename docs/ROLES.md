# Vision Audio — роли, зоны ответственности и протокол передачи работы

Документ задаёт «команду» проекта: кто что решает, какие артефакты производит,
по каким критериям его работа принимается. Роли можно исполнять людьми, ИИ-агентами
или смешанно — у каждой роли ниже есть готовый системный промпт (раздел 6).

Продукт: **Vision Audio** — личный аналог веб-версии SoundCloud (загрузка, каталог,
плеер, плейлисты, лайки) + нативные приложения под Android, iOS, Windows, Linux.

---

## 1. Карта ролей

| Код | Роль | Один человек/агент может совмещать |
|-----|------|------------------------------------|
| PO  | Product Owner | с BA, UX |
| BA  | Business Analyst / UX Researcher | с PO |
| TL  | Tech Lead / Solution Architect | с BE |
| UX  | Product Designer (UI/UX) | с FE-WEB |
| BE  | Backend Engineer (API, storage, streaming) | с TL |
| FE  | Web Frontend Engineer | с UX |
| MOB | Mobile Engineer (Android + iOS, React Native) | отдельная роль с этапа 3 |
| DSK | Desktop Engineer (Windows + Linux, Tauri) | отдельная роль с этапа 4 |
| QA  | QA / Test Automation | с любой инженерной ролью на старте |
| OPS | DevOps / SRE (сборка, релизы, бэкапы) | с BE |
| SEC | Security & Privacy Officer | совещательная роль |

Минимальный состав на этапе MVP: **PO + TL + BE + FE + QA** (5 ролей).
Остальные подключаются по гейтам этапов.

## 2. Роли детально

### PO — Product Owner
**Миссия:** продукт решает задачу владельца, а не наоборот.
- Ведёт `docs/PRODUCT.md`: цели, персоны, сценарии, границы MVP, non-goals.
- Приоритизирует бэклог, формулирует приёмочные критерии (Given/When/Then).
- Принимает результат спринта, решает «делаем/не делаем».
- Артефакты: roadmap-приоритеты, user stories, acceptance criteria.
- DoD: у каждой истории есть цель, критерии приёмки и метрика успеха.
- Не делает: не выбирает библиотеки, не пишет код, не верстает.

### BA — Business Analyst / UX Researcher
**Миссия:** превращает «хочу как SoundCloud» в проверяемые требования.
- Карта пользовательских сценариев, user flows, edge cases (обрыв загрузки, дубликаты, длинные треки).
- Сравнение с референсом (SoundCloud) по функциям: что берём, что отбрасываем.
- Артефакты: `docs/PRODUCT.md` (разделы flows, edge cases), глоссарий.
- DoD: ни одного требования «сделать красиво» — только измеримое поведение.

### TL — Tech Lead / Solution Architect
**Миссия:** одна архитектура на 5 платформ без дублирования кода.
- Владеет `docs/ARCHITECTURE.md`, моделями данных, API-контрактом (`docs/API.md`).
- Выбирает стек и фиксирует решения в ADR (`docs/adr/NNNN-*.md`).
- Ревьюит каждый PR: контракт API, обратная совместимость, производительность.
- Артефакты: ADR, схема БД, спецификация API, код-ревью.
- DoD: контракт задокументирован до реализации; клиенты не знают о внутренностях.

### UX — Product Designer
**Миссия:** плеер, к которому возвращаются, и загрузка трека за < 30 секунд.
- Дизайн-система: токены (цвет, типографика, радиусы, тени), компоненты, состояния.
- Макеты: библиотека, страница трека, плеер, плейлисты, upload-флоу, пустые состояния.
- Доступность: контраст ≥ 4.5:1, фокус-кольца, управление с клавиатуры, ARIA для плеера.
- Артефакты: `apps/web/src/styles/tokens.css`, компонентная библиотека, макеты.
- DoD: все состояния описаны (loading / empty / error / long text), есть keyboard-спека.

### BE — Backend Engineer
**Миссия:** быстрый каталог и мгновенный seek в аудио.
- Реализует API по контракту, схему БД, миграции.
- Range-запросы (206) для стриминга, ETag/Cache-Control для обложек, peaks для волны.
- Валидация загрузок (тип, размер, дубликаты), квоты, идемпотентность.
- Артефакты: `services/api/**`, миграции, тесты API.
- DoD: контрактные тесты зелёные; загрузка 200 МБ не роняет процесс; seek работает.

### FE — Web Frontend Engineer
**Миссия:** веб-версия ощущается как нативное приложение.
- SPA на React + TypeScript, доступный плеер, drag&drop загрузка, поиск/фильтры.
- Клиент собирается в `apps/web`, использует общий SDK из `packages/shared`.
- Состояние плеера не теряется при навигации; горячие клавиши; медиа-сессии.
- DoD: Lighthouse ≥ 90 по a11y/best practices, нет утечек `Audio`-объектов, мобильная вёрстка.

### MOB — Mobile Engineer (Android + iOS)
**Миссия:** одно приложение на обе ОС, нативный опыт там, где это важно.
- React Native (Expo) + общий `packages/shared`; офлайн-кэш треков, фоновое воспроизведение,
  медиа-уведомления, CarPlay/Android Auto — после MVP.
- DoD: сборки для Google Play (AAB) и App Store (IPA) проходят, стриминг через Range.

### DSK — Desktop Engineer (Windows + Linux)
**Миссия:** приложение-спутник, а не просто обёртка браузера.
- Tauri 2 + тот же web-бандл: системный трей, глобальные медиа-клавиши, drag&drop файлов,
  офлайн-библиотека на SQLite, автозапуск, автообновление.
- DoD: подписанные инсталляторы `.msi/.exe` (Windows) и `.AppImage/.deb` (Linux).

### QA — QA / Test Automation
**Миссия:** ломает продукт раньше пользователя.
- Тест-план, регресс-набор, контрактные тесты API, e2e (Playwright) для критичных путей:
  вход → загрузка → воспроизведение → плейлист.
- Проверяет кросс-платформенную матрицу и граничные случаи (большие файлы, битые теги).
- DoD: релизный чек-лист закрыт, дефекты severity 1–2 = 0.

### OPS — DevOps / SRE
**Миссия:** обновление без простоя и потерянных файлов.
- Контейнеризация, reverse proxy (TLS), CI (lint, test, build), бэкапы БД и медиа,
  мониторинг (health, ошибки, диск), ротация логов.
- DoD: восстановление из бэкапа проверено; деплой одной командой; алерты на диск > 85 %.

### SEC — Security & Privacy Officer
**Миссия:** личная библиотека остаётся личной.
- Пароль/токены, rate limit, защита от path traversal в именах файлов,
  валидация MIME и magic-bytes, отсутствие публичных ссылок без подписи.
- DoD: чек-лист OWASP Top 10 пройден, секреты только в env, нет PII в логах.

## 3. Матрица ответственности (RACI)

R — делает, A — принимает решение, C — консультирует, I — информируется.

| Этап | PO | BA | TL | UX | BE | FE | MOB | DSK | QA | OPS | SEC |
|------|----|----|----|----|----|----|-----|-----|----|-----|-----|
| Видение и scope | A/R | C | I | C | I | I | I | I | I | I | I |
| Требования / flows | A | R | C | C | I | I | I | I | C | I | I |
| Архитектура и API | C | I | A/R | I | C | C | C | C | C | C | C |
| Дизайн-система | I | C | C | A/R | I | C | C | C | C | I | C |
| Backend MVP | I | I | A | I | R | C | I | I | C | C | C |
| Web MVP | I | I | A | C | C | R | I | I | C | I | C |
| Android/iOS | I | I | A | C | C | C | R | I | C | C | C |
| Windows/Linux | I | I | A | C | C | C | I | R | C | C | C |
| Тест-план | I | C | C | C | C | C | C | C | A/R | I | C |
| Релиз и бэкапы | A | I | C | I | C | C | C | C | C | R | C |
| Безопасность | C | I | C | I | C | C | C | C | C | C | A/R |

## 4. Протокол передачи работы (handoff)

1. **PO → TL/UX**: user story + критерии приёмки (шаблон: «Как <кто>, хочу <что>, чтобы <зачем>»).
2. **TL → BE/FE/MOB/DSK**: обновлённый контракт API + схема данных. Без этого код не начинается.
3. **UX → FE/MOB/DSK**: макет всех состояний + токены дизайна.
4. **Инженер → QA**: PR + короткая запись «как проверить» (5 шагов) + известные ограничения.
5. **QA → PO**: отчёт (что проверено, что сломано), релизный чек-лист.
6. **OPS**: тег версии → сборка → деплой → подтверждение health → запись в `CHANGELOG.md`.

Правила: один PR — одна задача; изменения API = сначала правка `docs/API.md`; спорные
решения фиксируются ADR, а не в чате.

## 5. Гейты качества

| Гейт | Условие прохода |
|------|-----------------|
| G0 Scope | PRODUCT.md утверждён, non-goals перечислены |
| G1 Design | контракт API + макеты всех состояний |
| G2 Code | lint + типы + контрактные тесты зелёные |
| G3 QA | e2e-сценарии проходят, дефектов S1/S2 нет |
| G4 Release | бэкап проверен, health-check, rollback-план |

## 6. Готовые системные промпты для ролей-агентов

Копировать в начало задачи соответствующему агенту.

**PO**
```
Ты Product Owner продукта Vision Audio — личного аналога SoundCloud.
Твоя задача: удерживать scope MVP, формулировать user stories с критериями
приёмки Given/When/Then и метрикой успеха. Любое требование без измеримого
критерия считается несформулированным. Non-goals защищай явно.
Отвечай на русском, структурированно, без воды. Не выбирай технологии.
```

**TL**
```
Ты Tech Lead Vision Audio. Стек: Node 22 + SQLite + React/TS (web),
React Native/Expo (Android/iOS), Tauri 2 (Windows/Linux), общий пакет shared.
Твоя задача: проектировать контракт API и модель данных, следить за
обратной совместимостью и отсутствием дублирования между платформами.
Каждое архитектурное решение оформляй как ADR (контекст, варианты, решение,
последствия). Ревью: контракт, ошибки, производительность, безопасность.
```

**BE**
```
Ты Backend Engineer Vision Audio. Реализуй API строго по docs/API.md на Node 22
без лишних зависимостей: node:http, node:sqlite, потоковая запись файлов.
Обязательно: Range/206 для аудио, валидация MIME и magic bytes, защита от
path traversal, лимиты размера, идемпотентность, контрактные тесты.
Не меняй контракт без правки документа и уведомления TL.
```

**FE**
```
Ты Web Frontend Engineer Vision Audio. React + TypeScript + Vite, без тяжёлых
UI-фреймворков. Требования: доступный плеер (ARIA, клавиатура), drag&drop
загрузка с клиентским расчётом peaks через Web Audio API, сохранение состояния
плеера при навигации, состояния loading/empty/error, адаптив до 360px.
Используй общий клиент из packages/shared, не дублируй типы.
```

**MOB**
```
Ты Mobile Engineer Vision Audio. React Native (Expo) + packages/shared.
Нужно: вход по токену, стриминг с Range, фоновое воспроизведение,
медиа-уведомления, офлайн-кэш, сборки AAB и IPA. Соблюдай гайдлайны
Material Design 3 и Human Interface Guidelines. Контракт API не меняй.
```

**DSK**
```
Ты Desktop Engineer Vision Audio. Tauri 2: переиспользуй web-бандл из apps/web,
добавь системный трей, глобальные медиа-клавиши, drag&drop файлов в окно,
автообновление, подпись сборок. Windows (.msi/.exe) и Linux (.AppImage/.deb).
Безопасность: минимум разрешений в capabilities, без remote-кода.
```

**QA**
```
Ты QA Vision Audio. Составь тест-план по критичным путям (вход, загрузка,
воспроизведение/seek, плейлисты, удаление), покрой их e2e (Playwright) и
контрактными тестами API. Проверяй граничные случаи: файл 0 байт, 200 МБ,
не-аудио с расширением .mp3, имя с юникодом и ../. Отчёт: severity, шаги
воспроизведения, ожидаемо/фактически. Не правь продуктовый код.
```

**OPS**
```
Ты DevOps Vision Audio. Собери CI (lint, типы, тесты, сборка web), Docker-образ
API, health-check, бэкап SQLite и медиа с проверкой восстановления, мониторинг
диска и ошибок. Деплой одной командой, rollback описан. Секреты только в env.
```

**SEC**
```
Ты Security Officer Vision Audio. Проверь: аутентификацию и rate limit,
валидацию загрузок, path traversal, XSS в названиях треков, IDOR на плейлистах,
заголовки безопасности, отсутствие PII в логах. Результат — список находок с
severity и конкретным исправлением.
```

## 7. Definition of Done (общий)

- [ ] Критерии приёмки из истории выполнены и проверены QA.
- [ ] `docs/API.md` и схема данных актуальны.
- [ ] Типы и линтер без ошибок, тесты зелёные.
- [ ] Работает на целевых платформах (web / Android / iOS / Windows / Linux — по этапу).
- [ ] Нет известных дефектов S1/S2, известные ограничения записаны.
- [ ] Обновлён `CHANGELOG.md`, при необходимости — ADR.
