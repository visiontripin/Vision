# Контент: что и как добавляем

Документ отвечает на два вопроса: **как наполнить библиотеку** и **что можно
взять из SoundCloud, не нарушая их правила и авторские права**.

## Коротко

| Способ | Что получаем | Звук откуда | Годится для офлайна |
| --- | --- | --- | --- |
| Свои файлы (drag&drop, папка, `npm run seed`) | полный трек: волна, обложка, теги, дедуп | наш диск | да |
| Легально купленные/скачанные файлы (Bandcamp, CC-музыка, собственные записи) | то же | наш диск | да |
| **Ссылки SoundCloud** (раздел «Из SoundCloud») | закладка: название, автор, официальный плеер | серверы SoundCloud | нет |

**Чего мы не делаем:** не скачиваем аудио со SoundCloud, не парсим их страницы,
не проксируем поток через наш сервер, не кэшируем чужие файлы и обложки, не
обходим ограничения доступа. Это прямо запрещено их условиями и нарушает
авторские права исполнителей.

## Почему нельзя «просто скачать» с SoundCloud

1. **Условия сервиса.** SoundCloud не разрешает выгружать чужой контент; их API
   выдаёт `stream_url` только для воспроизведения в рамках их правил, а не для
   сохранения файла. Регистрация новых приложений в публичном API закрыта,
   публичные ресурсы с 2021 года требуют `client_credentials`.
2. **Авторские права.** Трек на SoundCloud принадлежит автору/правообладателю,
   а не платформе. «Для личного пользования» не делает копию легальной.
3. **Технически это хрупко.** Любой риппер ломается от изменений в их защите и
   тянет за собой юридические риски — не тот фундамент для личной библиотеки.

Поэтому вместо копирования мы даём **закладку на официальный плеер**: он играет
с их серверов, наши диск, трафик и бэкапы не расходуются.

## Раздел «Из SoundCloud» — как устроен

1. Вы вставляете ссылку вида `https://soundcloud.com/artist/track`.
2. Сервер проверяет домен по allowlist (`soundcloud.com`, `www`, `m`, `on`),
   нормализует ссылку (убирает `?si=…`, якоря) и обращается к **официальному
   oEmbed-эндпоинту** `https://soundcloud.com/oembed?format=json&url=…`.
3. Из ответа берём только `title`, `author_name`, `thumbnail_url` и `src`
   встроенного плеера (iframe обязан смотреть на `w.soundcloud.com/player`).
4. В БД попадает запись: `permalink`, `title`, `artist`, `embed_url`, заметка.
   Аудио, длительность, волна и обложка **не копируются** (обложка у нас —
   собственная градиентная заглушка, без хотлинка).
5. Кнопка «Слушать» разворачивает официальный iframe. CSP разрешает фреймы
   только с `w.soundcloud.com` — всё остальное браузер заблокирует.

Ограничения раздела: нужен сервер (в статической GitHub Pages версии раздела нет),
нет волны и офлайн-прослушивания, удалённый трек покажет ошибку в плеере.
Повторный импорт той же ссылки обновляет метаданные, а не создаёт дубль.

## Как добавить свой контент

### Через интерфейс

Перетащите файлы в окно — волна считается в браузере (Web Audio), теги и обложка
читаются сервером из файла, дубликаты по SHA-256 отклоняются с подсказкой.

### Демо-библиотека (для проверки плеера)

```bash
npm start          # в первом терминале
npm run seed       # во втором: 9 синтезированных треков + 2 плейлиста
```

Треки генерируются скриптом (синусоиды, аккорды, простой бит), поэтому это
безопасно с точки зрения прав и не требует интернета.

### Массовый импорт: папка или ZIP

1. «Загрузить» → **«Папка»** — выбираете каталог, браузер отдаёт все файлы внутри
   (включая вложенные). Поддерживается Chrome, Edge, Firefox, Safari 16+.
2. **Перетаскивание папки** прямо в окно — то же самое через `webkitGetAsEntry`.
3. **ZIP-архив** — перетащите `.zip` или выберите его в диалоге. Архив разбирается
   локально в браузере: центральный каталог читаем сами, `deflate` распаковывает
   встроенный `DecompressionStream('deflate-raw')`. Никаких зависимостей и
   серверной распаковки; на сервер уходят уже готовые аудиофайлы.
4. Перед загрузкой каждый файл анализируется (длительность + 180 пиков), затем
   идёт очередь с прогрессом по каждому файлу.

Что происходит с «лишним»: `.txt`, обложки, `__MACOSX/`, `.DS_Store` и скрытые
файлы отбрасываются; повторы (тот же SHA-256) показываются как «уже в библиотеке»
и не считаются ошибкой. В конце — сводка: загружено / дубликатов / ошибок.

Ограничения: ZIP64 и зашифрованные архивы пропускаются (обычные архивы из Finder,
Explorer и `zip -r` работают), больше 2000 треков из одного архива за раз не берём.

### Массовый импорт своих файлов

```bash
for f in ~/Music/legal/*.mp3; do
  curl -s -X POST "localhost:4000/api/v1/tracks?filename=$(basename "$f")" \
    -H "Authorization: Bearer $TOKEN" \
    -H "Content-Type: audio/mpeg" \
    --data-binary @"$f"
done
```

Метаданные (исполнитель, альбом, обложка) подтянутся из тегов файла; название
из имени файла — только если тегов нет.

## Где брать музыку легально

- **Свои записи и чужие с разрешения** — лучший источник: полный контроль прав.
- **Bandcamp** — покупка даёт файлы (mp3/flac/wav); их можно хранить у себя.
- **Free Music Archive, Jamendo, ccMixter, Internet Archive** — лицензии Creative
  Commons: смотрите условия атрибуции, они разные.
- **Промо-релизы лейблов** (free downloads, remix-паки) — если условия разрешают
  личное использование.
- **SoundCloud** — только ссылки-закладки, как описано выше; для офлайна у них
  есть своё приложение (Go+), и это их право решать, как слушать офлайн.

## Если библиотекой будут пользоваться близкие (Фаза 6)

Правило простое: **раздавать можно только то, на что у вас есть права** —
свои записи или контент с лицензией, допускающей распространение. Закладки на
SoundCloud раздавать безопасно: каждый слушатель открывает их сам, у себя.
