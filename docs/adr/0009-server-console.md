# 0009. Панель запуска и администрирования — отдельное приложение

**Дата:** 2026-11-10
**Статус:** принято (v0.15.0 / console 0.1.0)
**Роли:** TL, BE, OPS, MOB, DSK, UX

## Контекст

До сих пор всё жило в одном веб-интерфейсе и одном Expo-приложении:

- эксплуатация (что с сервером, сколько места, какие ссылки открывали) требовала
  помнить curl-команды из `docs/RUNBOOK.md` или лезть в БД;
- на Android сервер поднимается в Termux, но узнать «почему не играет» с телефона
  было нечем — приложение-плеер показывает ошибку и всё;
- владелец просил вынести запуск сервера и админку в **отдельное приложение для
  Android и Windows**.

Требования, вытекающие из продукта:

1. То же приложение должно работать и в браузере: панель нужна на сервере по `/admin`
   (в том числе как `redirect_url` для мини-аппа Telegram, которому нужен HTTPS-адрес).
2. Никакого дублирования контракта: панель говорит с тем же API, что и остальные клиенты.
3. Минимум прав: панель не должна уметь запускать команды и читать файлы — иначе это
   готовый RCE-канал в домашней сети.

## Решение

### 1. Отдельное приложение `apps/console`, а не вкладка в `apps/web`

Tauri 2: одна кодовая база → окно Windows (`.msi`/`.exe`) и APK Android.
Почему Tauri, а не React Native/Expo (как `apps/mobile`):

- панели нужен **тот же веб-бандл**, что и в браузере: одна логика, ноль платформенных
  ветвлений в интерфейсе;
- Android-сборка Tauri получает Rust+NDK, но это отдельная джоба CI и не влияет на
  проверку панели на PR;
- APK ~5–10 МБ вместо ~50 МБ — панель не тащит expo-av и офлайн-кэш.

Плеер (`apps/web`, `apps/mobile`, `apps/desktop`) не тронут: у слушателя и у владельца
разные задачи и разные поверхности.

### 2. Сервер отдаёт панель по `/admin`

`apps/console/dist` — обычная статика. `serveConsole()` отдаёт её так же, как веб-сборку,
но с отдельными правилами:

- `/admin` → `index.html`, `/admin/assets/*` → файлы (иначе SPA-фолбэк отдавал бы HTML
  вместо JS и панель не запускалась);
- SPA-роуты панели (`/admin/settings/...`) не дают 404;
- `X-Robots-Tag: noindex` — админку не индексируют;
- если панель не собрана — **503 с инструкцией** `npm run build:console`, а не пустая
  страница: человек должен понять, что делать.

Это же решает вопрос с Telegram: `redirect_url` мини-аппа может указывать на
`https://<домен>/admin`, отдельный хостинг не нужен.

### 3. Приложение проверяет сервер, но не запускает его

Запуск процесса из оболочки соблазнителен («кнопка Старт»), но:

- на Android Node в Termux — отдельный мир, из APK его не поднять без прав;
- на Windows это означало бы держать в приложении копию Node и путь к `DATA_DIR`,
  права на файлы и обновления — то есть второй менеджер сервисов.

Поэтому панель делает то, что реально нужно: **проверяет связь и объясняет состояние**.
Права Tauri ограничены `core:default` + собственной командой `platform()`. Ни `shell`,
ни `fs` — даже если панель скомпрометируют, запустить команду ей нечем.

### 4. Диагностика — код, а не текст в разметке

`src/lib.ts` (`diagnose`, `diskState`, `humanBytes`, `expiry`, `ago`) — чистая функция
без DOM. Она переводит `/api/health` в список «зелено/жёлто/красно» с человеческим
объяснением: мало места, не применены миграции, нет ffmpeg, есть файлы без источника,
не задан `PUBLIC_URL`, сервер не отвечает.

Смысл: одна и та же проверка используется в панели, в тестах и (при желании) в CI —
а не расползается по трём экранам словами.

## Последствия

- Новая папка `apps/console` (npm-workspace), новый workflow `.github/workflows/console.yml`
  с тремя джобами: `check` (на каждый PR), `windows`, `android`.
- Тесты: 8 проверок чистой логики (`apps/console/src/lib.test.ts`) + 6 контрактных
  проверок отдачи `/admin` (`services/api/test/console.test.js`).
- `SECURITY_TXT` (CSP страниц сервера) уже содержит `connect-src 'self'` — панель на
  своём origin ничего не требует; при подключении к внешнему адресу работает APK/окно,
  где CSP Tauri задан в `tauri.conf.json` (`connect-src 'self' http: https:`).
- Панель **не** заменяет `docs/RUNBOOK.md`: она показывает состояние, но решения
  (бэкап, восстановление, ротация секретов) остаются процедурами.
- Не делаем: управление пользователями (ролей нет), загрузку файлов из панели
  (это делает плеер), просмотр логов (дальше — `G10`, аудит и журнал шаринга).
