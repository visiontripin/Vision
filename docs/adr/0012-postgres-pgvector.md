# 0012. Postgres + pgvector для публичного контура

**Дата:** 2026-11-12
**Статус:** принято как целевая архитектура Ф1; миграция не начата
**Роли:** TL, BE, DATA, OPS

## Контекст

Текущий API использует SQLite и рассчитан на личную библиотеку. Публичный каталог, многопользовательские записи, события и рекомендации требуют конкурентной записи и векторного поиска.

## Решение

Для серверного публичного контура использовать PostgreSQL; расширение `pgvector` хранит и ищет аудио-эмбеддинги. SQLite остаётся для локального режима и совместимости уже работающего личного плеера, но не является целевым источником публичного UGC.

## Ограничения и последствия

- Перенос данных планировать отдельно с нумерованными миграциями, проверкой counts/SHA-256, backup и rollback.
- До принятого плана миграции существующий production/private режим не менять.
- Хостинг, стоимость, резервирование и подтверждение миграции остаются гейтами Ф1; сначала проверить нагрузку и восстановление.
