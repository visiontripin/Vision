# 0020. Vision Server для Windows — сохранённый эксперимент

**Дата:** 2026-11-12
**Статус:** реализация и workflow временно заморожены; Windows build/install/runtime не подтверждены; отдельное требование владельца остаётся неразрешённым
**Роли:** PO, TL, OPS

## Контекст

До pivot в ADR-0011 продукт рассматривался как личная аудиобиблиотека. После отмены встроенного Node в мобильном APK возникла отдельная идея устанавливаемого Vision Server для домашнего Windows-ПК. Она получила отдельный эксперимент в текущей Arena-ветке, но не является решением по платформе Vision Audio v2.

## Исторические варианты

1. Оставить мобильный APK сервером и плеером одновременно.
2. Оставить APK клиентом внешнего API и вынести домашний сервер в отдельную Windows-службу.
3. Оставить только API/клиентов без отдельного инсталлятора.

## Историческое решение и текущий статус

В рамках предыдущего технического эксперимента был выбран вариант 2: подготовить Windows NSIS `.exe` с Node/API/FFmpeg/WinSW, собственной службой, автозапуском и данными в `%ProgramData%`. Код и предварительные инструкции сохранены в репозитории.

Позднее product scope изменён: ADR-0011 задаёт переход к платформе независимой музыки, а Ф0.4 временно замораживает desktop/console/embedded workflow до подтверждения PMF. Поэтому автоматические сборки и публикации сейчас выключены; код сохранён и не подтверждён на Windows. При этом владелец отдельно задал требование к Windows-службе, автозапуску и администраторскому установщику. Этот ADR и временная заморозка **не отменяют** требование: конфликт между ним и сроком/исключением для platform freeze остаётся открытым. Нужен явный выбор владельца; не заявлять сервер завершённым, протестированным либо отменённым. Мобильный плеер остаётся API-клиентом; встроенный Node в APK удалён.

## Ограничения проверки

В репозитории имеются NSIS hooks, Windows runtime и сценарий установки/проверки службы. Они не подтверждены реальной Windows-сборкой, установкой, UAC, ACL/SCM, автозапуском после перезагрузки, Node/FFmpeg runtime или удалением. Код не считать пригодным к релизу или поддерживаемым пользователями.

Для будущего возобновления потребуются: отдельное решение PO, обновлённый ADR, разблокировка CI/релизного workflow, полная проверка на чистой Windows-машине, review безопасности и актуальные инструкции. До этого `docs/HOME-SERVER-WINDOWS.md` — только архивная инженерная заметка, не руководство к установке.

## Последствия

- Код сохраняется, но остаётся вне активного roadmap и может быть удалён только отдельным решением владельца.
- Автоматический build/release отключается; workflow остаётся ручным и без публикации для будущего аудита.
- Не рекомендовать устанавливать неподтверждённый код и не обещать срок поддержки; это не отменяет открытое требование владельца. Перед дальнейшей работой требуется разрешить конфликт с ADR-0016.
