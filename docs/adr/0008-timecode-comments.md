# 0008. Таймкод-комментарии для приглашённых

**Дата:** 2026-11-10
**Статус:** принято (v0.14.0, Фаза 6 / E3)
**Роли:** BE, FE, SEC, UX

## Контекст

Приватная ссылка (ADR 0007) даёт другу «послушать микс», но не даёт сказать
«вот тут вступает бас». В SoundCloud это главный социальный элемент: комментарий
привязан к секунде и виден всем, кто слушает тот же трек.

Нужно решить четыре вещи: где живёт комментарий, кто его видит, как считать
«свой» без аккаунтов и как это работает без JavaScript (гостевая страница
сейчас SSR, без бандла).

## Решение

### 1. Комментарий принадлежит ссылке, а не треку

Таблица `share_comments(share_id, track_id, at_seconds, author, author_hash, body,
created_at, deleted_at)` — ключ ленты это **пара «ссылка + трек»**.

Почему не «комментарий к треку глобально»: у владельца может быть одна и та же
песня в разных миксах для разных людей. Глобальная лента смешала бы «для мамы»
и «для коллег», и любой, кому ушла одна ссылка, увидел бы весь тред. Изоляция по
ссылке — продолжение модели ADR 0007: **один токен = одна видимая поверхность**.

Владелец видит ленты всех своих ссылок через `/api/shares/:id/comments`
(включая удалённые — для разбора), гость — только через токен.

### 2. Приватность: никакого своего «аккаунта»

- `author` — свободное имя, которое гость вводит сам (до 40 символов), по
  умолчанию «Гость». Имя не проверяется: это записка, а не удостоверение.
- `author_hash = sha256(VISION_SECRET + ':' + ip)` — только чтобы понять «свой ли
  комментарий» и притормозить спам. Сырого IP нет ни в БД, ни в логах.
- Удалять может автор (совпадение хеша) или владелец библиотеки. Чужой гость
  получает `403`, повторное удаление — `ids` уже нет, поэтому `404`/`403` без
  подсказки «был ли комментарий».
- Комментарии **не** попадают в поиск, OG-карточку и статистику ссылки: они
  видны только на странице с токеном.

### 3. Валидация на сервере, а не в вёрстке

- `at` клампится в `0..duration` (если длительность известна): «на 900-й секунде»
  двухминутного трека не появится.
- Тело — до 600 символов, имя — до 40; управляющие символы вырезаются, серии
  пробелов схлопываются, переводы строк сохраняются.
- Всё выводится через HTML-экранирование; единственные активные элементы
  страницы — наши собственные `<audio>`, `<form>` и короткий inline-скрипт.
- Троттлинг: не больше 8 комментариев в минуту с одного адреса по одной ссылке
  (`429 too_many`). Это не защита от ботов, а защита ленты от «залил 200 строк».

### 4. Работает без JavaScript

Страница гостя остаётся SSR. Комментарии рендерятся сервером, форма — обычный
`POST /s/<token>/comments` с `application/x-www-form-urlencoded` и ответом `303`
обратно на `#track-<id>`. Скрипт (inline, ~40 строк) — только удобство:
подставляет текущую секунду плеера в скрытое поле и перематывает по клику на
таймкод, если JS включён.

CSP гостевой страницы расширена ровно на необходимое: `script-src 'unsafe-inline'`
(наш скрипт) и `form-action 'self'` (наша форма). `default-src 'none'` остаётся,
внешних запросов по-прежнему нет.

## Последствия

- Новая миграция `009-share-comments`; удаление ссылки с `?purge=1` уносит и
  комментарии (FK-каскад не полагаемся — `DELETE` делаем явно).
- Отозванная/истёкшая ссылка перестаёт отдавать ленту: `410` **JSON**, а не HTML,
  потому что ленту читает код, а не человек.
- Метрика `vision_share_comment_total`.
- Известное ограничение: троттлинг считается в памяти процесса — после рестарта
  счётчик обнуляется. Для домашнего сервера это приемлемо; для публичного нужен
  счётчик в БД (см. `docs/IMPROVEMENTS.md`, G10 — аудит и журнал шаринга).
- Не делаем: ответы на комментарии, реакции, уведомления, модерацию по словарю.
  Это уже «соцсеть», от которой PRODUCT.md явно отказывается.
