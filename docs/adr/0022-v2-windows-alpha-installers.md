# 0022. Windows installer и клиент для внутренней alpha v2

**Дата:** 2026-11-12
**Статус:** принято владельцем как целевой способ поставки; реализация отложена до Stack Ready
**Роли:** PO, TL, OPS, SEC, FE, QA

## Контекст

Владелец выбрал закрытую внутреннюю alpha v2 на одном серверном ПК и клиентских ПК с Windows 10/11. Целевые сценарии — артист и слушатель, включая radio/recsys. Владелец запросил отдельный Windows `.exe`-установщик сервера и Windows `.exe`-клиент для v2.

Владелец сохранил строгий порядок ADR-0021: Stack Ready должен быть полностью проверен и явно принят до новых app-фич и сборки клиентского приложения. Ветка пока не готова к alpha: v2 web UI не реализован, LAN/VPN-модель не выбрана, Windows server/runtime smoke не пройден.

Наличие старых экспериментов не закрывает запрос: `apps/console` упаковывает legacy SQLite API, а `apps/desktop` — прежний web-плеер личной библиотеки. Они не являются v2 EXE и не должны выдаваться за них. Их workflows заморожены по ADR-0016/0020.

## Решение

1. После явной приёмки Stack Ready подготовить два **внутренних alpha-артефакта** для Windows 10/11 x64:
   - server setup `.exe` для установки/управления v2 на одном серверном ПК;
   - client `.exe` для artist/listener UI с radio/recsys-сценариями.
2. Сохранить ADR-0021 без исключений: до Stack Ready не начинать новые продуктовые UI/client-фичи и не собирать новый v2 client `.exe`.
3. Узкое разрешение на эти v2 Windows-артефакты действует только после Stack Ready и только для закрытой внутренней alpha. Это исключение к заморозке ADR-0016 не снимает freeze для legacy `apps/desktop`, `apps/console`, Android server или публичных релизов.
4. Клиентский EXE должен доставлять v2 web UI, а не старую личную библиотеку. Его точный desktop/webview wrapper выбирается после gate и отдельного технического review.
5. Server setup — **установщик, не один самодостаточный бинарник API**: v2 зависит от PostgreSQL/pgvector, Redis, S3-compatible storage, API и worker. Предварительная основа — один серверный хост с существующим Docker Compose и Docker Desktop + WSL2, но это не финальное решение по установке, автозапуску или жизненному циклу сервисов.
6. До отдельного packaging/security ADR нельзя автоматически устанавливать Docker, менять Windows Firewall/роутер, открывать API/MinIO/DB/Redis или создавать доступ из интернета. Клиентский доступ будет добавлен только после принятия LAN/VPN-плана и проверки TLS и browser-to-storage подписанных URL.
7. Артефакты предназначены только для контролируемого внутреннего теста; публичная публикация и внешний набор участников требуют отдельного Go/no-go.

## Последствия

- Целевые EXE зафиксированы; их наличие не подразумевается. Проверенных v2 Windows-установщиков сейчас нет.
- Перед реализацией нужен отдельный план упаковки: Compose/orchestrator или Windows service, prerequisites, автозапуск, secrets/data directories, backup/restore, обновление/удаление, installer signing и восстановление после сбоя.
- Будущий client `.exe` зависит от готового v2 web UI, выбора защищённого server origin и тестирования артист/слушатель/radio E2E на Windows.
- Требования к Windows-службе, автозапуску и admin/per-machine установке, ранее зафиксированные в ADR-0020, нужно явно разрешить в packaging ADR для **v2**; legacy реализацию автоматически не возобновлять.
- Проверку проводить на чистом Windows 10/11 x64: install, start/stop/reboot, обновление и uninstall, права файлов, backup/restore, отсутствие незапланированного сетевого доступа, доступ клиентских ПК только по выбранному защищённому маршруту.

## Как проверим

- Stack Ready отдельно принят владельцем; hosted CI или наличие исходников не заменяют приёмку.
- Windows installer и client build проходят на выделенной Windows runner/чистой тестовой машине; контрольные суммы артефактов сохранены.
- Серверный стек переживает повторный запуск/перезагрузку и восстановление; Postgres/Redis/storage не доступны напрямую извне.
- С клиентского ПК v2 client `.exe` выполняет artist profile/upload/status и listener catalog/play/radio/recsys/skip/feedback на разрешённом тестовом материале.
- TLS, подписанные media URL, CORS и недоступность quarantine/чужих объектов проверены; никакой router port-forward не включён.
