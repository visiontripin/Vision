# ADR 0001 — SQLite вместо Postgres

**Контекст.** Личная библиотека, один пользователь, сервер на VPS/NAS. Postgres даёт
конкурентность и репликацию, но требует администрирования, памяти и бэкап-процедур.

**Рассмотренные варианты.** Postgres (мощно, тяжело), SQLite (нулевое администрирование),
JSON-файлы (нет транзакций и индексов).

**Решение.** SQLite (`node:sqlite`, WAL). Медиа — на диске, метаданные — в БД.

**Последствия.** Бэкап = два файла + папка медиа. Ограничение — один писатель; для личного
использования это незаметно. При росте до мультипользовательского сценария миграция на
Postgres затрагивает только `services/api/src/db.js`.
