# 0016. Заморозить desktop/console и встроенный сервер до PMF

**Дата:** 2026-11-12
**Статус:** временная заморозка workflow применяется в scope Ф0.4; судьба Windows Vision Server остаётся открытым решением владельца
**Роли:** PO, TL, OPS

## Контекст

Репозиторий быстро набрал web, mobile, desktop, console и эксперименты со встроенным Node, при этом внешней аудитории ещё нет. Одновременное развитие платформ размывает фокус с прав, каталога и радио.

## Решение

До подтверждения product-market fit заморозить автоматические сборки и новые функции для `apps/desktop`, `apps/console` и встроенного Node в APK. Мобильный плеер остаётся клиентом внешнего API; его embedded-server код уже удалён. Существующие исходники и релизы не удаляются автоматически, но не считаются целевым roadmap v2.

**Открытое противоречие:** владелец ранее отдельно потребовал Vision Server для Windows как собственную службу с автозапуском и администраторским установщиком. Временная заморозка console/workflow в Ф0.4 не отменяет этот запрос и не подтверждает выполнение требования. Нужен отдельный выбор владельца — сохранить его с исключением/планом Windows-проверки либо явно пересмотреть. До этого Windows Server не считать shipped, tested или cancelled; см. ADR-0020 и `docs/HOME-SERVER-WINDOWS.md`.

## Последствия

- Автоматические desktop/console сборки и публикации не должны запускаться на обычных PR/tag событиях; ручная проверка допустима без публикации.
- Активный текущий Arena branch остаётся неприкосновенным; ветки с уже слитыми PR можно очистить после проверки статуса.
- Новые платформы не добавлять до гейта PMF.
