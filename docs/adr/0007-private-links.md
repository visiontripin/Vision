# ADR 0007 — Приватные ссылки на трек и плейлист

**Статус:** принято (v0.12.0, Фаза 6 / E1–E2)
**Контекст.** Библиотека личная, но «послушай мой микс» требует отправить другу
работающую ссылку. Отдавать гостю сессионный токен нельзя: он даёт доступ ко всей
библиотеке, живёт 30 дней и не отзывается. Публичный каталог противоречит non-goals
(`docs/PRODUCT.md` §3).

**Требования (PO/BA).**
- Ссылка открывается в инкогнито, без пароля и без регистрации.
- Гость видит и слышит **только** то, на что дана ссылка; поиск, лента и чужие треки
  недоступны (IDOR невозможен по построению, а не по проверке).
- Владелец задаёт срок жизни, лимит открытий, может отозвать и перевыпустить.
- В мессенджере ссылка разворачивается в карточку с названием и обложкой (OG-превью).
- Утечка дампа БД не должна давать рабочий URL.

**Рассмотренные варианты.**
1. *Сессионный токен в query* — отвергнуто: полный доступ, долгий срок, попадает в логи.
2. *HMAC-подпись на трек с TTL (как медиа-ссылки)* — дёшево, но нельзя отозвать
   конкретную ссылку, нет статистики и нет привязки к получателю.
3. *JWT с target и TTL* — отзыв только через чёрный список, токен длинный и заметный.
4. *Случайный 256-битный токен в пути + `sha256(token)` в БД* — **выбрано**.

**Решение.**
- `POST /api/shares` (владелец) создаёт запись `shares` и возвращает токен **один раз**
  (`/s/<token>`, 43 символа base64url). В БД — только `sha256(token)`; перевыпуск
  сохраняет старый хеш в `prev_token_hash`, чтобы старая ссылка отвечала `410 rotated`,
  а не `404`.
- Гостевые маршруты (`/s/:token`, `/stream/:trackId`, `/download/:trackId`,
  `/cover/:trackId`) не проходят через общий `authorized()`: токен — единственный ключ.
  Для ссылки на плейлист проверяется состав плейлиста, для ссылки на трек — совпадение id.
- Страница рендерится на сервере без JavaScript и без бандла: нативный `<audio>`
  (Range поддерживается), ссылка «Скачать», `noindex`, CSP `default-src 'none'` с
  `media-src`/`img-src`, разрешающими адреса сидов (файл может жить на другом узле роя).
  OG-теги (`og:type`, `og:title`, `og:image`) нужны мессенджерам, которые JS не выполняют.
- TTL по умолчанию 7 дней (`SHARE_DEFAULT_TTL_MS`), `ttl: "forever"` — бессрочно.
  Лимит открытий считает **открытия страницы**, а не Range-запросы: иначе один трек
  съедал бы лимит десятком запросов.
- Журнал `share_hits` хранит `sha256(secret + ip)` вместо IP: ответить «сколько разных
  людей открыло» можно, PII — нет.
- Удаление трека или плейлиста отзывает все его ссылки в той же операции.

**Последствия.**
- Восстановить ссылку нельзя — только перевыпустить (это осознанно: сервер не должен
  уметь показать действующий секрет).
- Хотя бы один сид должен быть жив: если файл не раздаётся, гость получает `409 no_source`,
  а страница остаётся доступной.
- OG-превью появится только при наличии обложки; без неё карточка — `summary`.
- Транскодированные варианты гостю пока не предлагаются (играется оригинал):
  добавлять выбор кодека в гостевой странице — отдельная задача Фазы 2.
- Ссылки не работают в локальном режиме (GitHub Pages): там нет сервера и адреса,
  который откроется у друга. UI честно это объясняет.
