# 0015. Политика реплик-сидов для UGC

**Дата:** 2026-11-12
**Статус:** proposed — требуется решение владельца после консультации LEGAL; не принято
**Роли:** SEC, LEGAL, PO, BE

## Контекст

Текущий API/трекер хранит записи о репликах; значения по умолчанию текущего личного сервера — `STORAGE_MODE=local`, `SEED_ENABLED` включён. Это существующее поведение личной библиотеки, не оценка его юридического статуса и не разрешение распространения публичного UGC.

Для публичного каталога нужны отдельные права и разрешения на копирование/распространение файла. Простое подтверждение при загрузке может быть недостаточно; права могут различаться для мастера, произведения, исполнителей, территорий, сроков и способов доступа. См. консультационный пакет `docs/legal/CONSULTATION-BRIEF.md`.

## Варианты для решения владельца

1. **Реплицировать только право-подтверждённый UGC.** Нужны проверяемая модель прав/территорий/срока, отдельное согласие на реплики, серверная проверка статуса, takedown и отзыв уже выданных ссылок.
2. **Отключить peer seeding для UGC.** Доставлять публичное медиа через контролируемый origin/S3/CDN; локальные копии остаются только в разрешённых режимах.
3. **Отложить решение.** До выбора владельцем не запускать публичный UGC/репликацию; не менять поведение личного режима без отдельного плана совместимости.

Плюсы, стоимость, применимые территории и ограничения должен подтвердить юрист. Агент не выбирает вариант вместо владельца.

## Временный безопасный гейт (не является выбором ADR)

- Публичные загрузки, публичная раздача и UGC-seeding остаются выключенными до выбора владельца и юридической проверки.
- Существующий private/local режим не объявляется проверенным или разрешённым; его конфигурация не меняется автоматически в рамках этого ADR.
- Если разработка публичного контура начнётся раньше окончательного выбора, она должна технически fail closed для peer replication.

## Вопросы к LEGAL/SEC

- Какие права нужны для каждой копии и каждого канала распространения?
- Как документировать права, территорию, срок, ограничения, права соавторов/лейбла?
- Что именно блокируется при notice/takedown, как инвалидировать сиды, кэш/CDN и ссылки?
- Как обеспечить аудит и не потерять законные личные/офлайн-копии?
