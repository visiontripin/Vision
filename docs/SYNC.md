# Общая библиотека между устройствами

Загрузили пять песен на телефоне — второе устройство с тем же приложением сразу
видит их в ленте. **В любой сети**, не только по домашнему Wi-Fi: в мобильном
интернете, в гостях, в другой стране.

## Почему не «сервер на телефоне»

Идея «каждое устройство — сервер» звучит просто, но в мобильной сети не работает:

| Что мешает | Что происходит |
| --- | --- |
| NAT у оператора | до телефона нельзя достучаться снаружи, даже зная адрес |
| Сон устройства | Android/iOS засыпают и закрывают входящие сокеты |
| Смена IP | адрес в мобильной сети меняется при каждом переподключении |
| Разные сети | два телефона в разных Wi-Fi друг друга не видят |

Поэтому в обмене участвует маленький **реестр** — один адрес, к которому
устройства ходят сами. Соединения всегда **исходящие**, значит сеть любая.

```
  Телефон A ─┐                                  ┌─ Телефон B
  (загрузил  │   POST /api/library (метаданные) │  (видит в ленте)
   5 песен)  ├──────────►  Реестр  ◄─────────────┤
             │   PUT  /api/library/:id/file      │
             └──────────►  (файл)  ◄─────────────┘  GET /api/library/:id/file
```

## Что делает приложение

1. Раз в 20 секунд отправляет метаданные своей библиотеки (`POST /api/library`) и
   получает в ответ всё, что знают остальные устройства.
2. Файлы догружает по одному за цикл (`PUT /api/library/:id/file`) — чтобы не
   забивать канал, если библиотека большая.
3. Чужой трек в ленте скачивается по требованию (`GET
   /api/library/:id/file`) и дальше играет как локальный, без сети.
4. Устройство «на связи», если отметилось за последние 15 минут. Пропало — его
   треки уходят из ленты (файлы в реестре остаются).

## Как включить

1. Поднимите реестр — это обычный сервер Vision (`docs/RUNBOOK.md`), доступный
   из интернета. Варианты:
   - VPS с доменом и HTTPS (рекомендуется);
   - туннель (Cloudflare Tunnel, Tailscale Funnel) к домашнему серверу;
   - домашний сервер, если устройства в одной сети.
2. В приложении подключитесь к этому серверу: **Настройки → Домашний сервер**
   (адрес и пароль). Реестр — это тот же сервер, отдельный адрес обычно не нужен.
   Если реестр живёт на другом адресе, укажите его в **Настройки → адрес
   реестра** (например `https://sync.example.com`).
3. Задайте **имя устройства** — так вас видно в ленте на других телефонах
   («Телефон A1», «Телефон Ани»).
4. Повторите на втором устройстве: тот же сервер (и тот же пароль).

Пока адрес не задан, приложение работает как локальный плеер и честно пишет об
этом в ленте: «Синхронизация не настроена».

## Что видно другим

Только метаданные: название, исполнитель, альбом, жанр, длительность, размер и
тип файла. Содержимое файла уходит в реестр один раз при загрузке и скачивается
тем, кто его открыл.

Доступ: `POST/GET /api/library` и `PUT/GET /api/library/:id/file` требуют токен
владельца — тот же, что у остальных `/api/*`. Человек в том же Wi-Fi без пароля
ничего не увидит. Это важно: реестр — ваша библиотека, а не публичный каталог.

## API

| Метод | Путь | Что делает |
| --- | --- | --- |
| `POST` | `/api/library` | отметиться и отдать свои треки; в ответ — все известные |
| `GET` | `/api/library` | снимок реестра без изменений |
| `PUT` | `/api/library/:id/file` | загрузить файл (тело-файл или multipart) |
| `GET` | `/api/library/:id/file` | скачать файл (Range поддержан) |
| `DELETE` | `/api/library/:id` | убрать трек и его файл из реестра |
| `GET` | `/api/library/devices` | живые устройства и размер библиотеки |

Ответ `POST /api/library`:

```json
{
  "version": 1,
  "devices": [{ "id": "dev-a", "name": "Телефон A", "baseUrl": null, "at": 1700000000000 }],
  "tracks": [{
    "id": "track-1", "title": "Вечер", "artist": "Кто-то", "duration": 200,
    "deviceId": "dev-a", "deviceName": "Телефон A",
    "downloadable": true, "updatedAt": 1700000000000
  }],
  "published": { "track-1": true },
  "accepted": 1, "rejected": 0
}
```

## Ограничения, которые стоит знать

- **Свой реестр обязателен.** Публичного общего сервера нет: библиотека личная, и
  данные не должны уходить третьим лицам.
- **Файлы лежат в реестре.** Это плата за «любую сеть»: телефон не может отдать
  файл напрямую. Занимаемое место считается в `GET /api/library/devices`.
- **Дубликаты схлопываются по `sha256`**: один и тот же файл, загруженный на двух
  телефонах, остаётся одним треком.
- **Удаление** трека из приложения убирает его из ленты, а файл в реестре остаётся
  до `DELETE /api/library/:id`.

## Проверка

```bash
# 1) отметиться первым устройством и отдать два трека
curl -s -X POST https://sync.example.com/api/library \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"device":{"id":"dev-a","name":"Телефон A"},"tracks":[{"id":"t1","title":"Проба","updatedAt":1700000000000}]}'

# 2) второе устройство видит трек
curl -s https://sync.example.com/api/library -H "Authorization: Bearer $TOKEN" | jq '.tracks[].title'

# 3) файл и перемотка
curl -s -X PUT https://sync.example.com/api/library/t1/file \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: audio/mpeg' --data-binary @song.mp3
curl -sI -H "Authorization: Bearer $TOKEN" -H 'Range: bytes=0-99' \
  https://sync.example.com/api/library/t1/file   # 206 Partial Content
```

Автотест этого сценария — `services/api/test/library.test.js` (два устройства,
загрузка, Range, multipart, закрытый доступ без токена, битые записи).
