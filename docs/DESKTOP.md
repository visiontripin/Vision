# Десктоп: Windows и Linux (Tauri 2)

Приложение — это тот же web-бандл (`apps/web/dist`), завёрнутый в Rust-оболочку
Tauri 2. Установщик ~6–12 МБ вместо ~100 МБ у Electron: системный WebView вместо
своего браузера, нативные трей, меню и глобальные клавиши.

**Статус v0.3.0.** Собирается в CI (`.github/workflows/desktop.yml` → `.deb`,
`.AppImage`, `.msi`/`.exe`), умеет трей, сворачивание в трей, медиа-клавиши и
**самообновление с проверкой подписи** (см. «Обновления»). Authenticode-сертификат
Windows подключается секретом в CI и без него установщик остаётся неподписанным.

## Что внутри

```
apps/desktop/
  package.json                 скрипты сборки и @tauri-apps/cli
  src-tauri/
    Cargo.toml                 tauri, plugin-global-shortcut, plugin-updater
    tauri.conf.json            окно, CSP, бандлы (msi, nsis, deb, appimage)
    capabilities/default.json  минимальные разрешения (core, shortcuts, updater)
    icons/                     PNG + .ico (генерируются `npm run icons`)
    src/main.rs                трей, медиа-клавиши, «свернуть в трей», команда player_state
apps/web/src/desktop.ts        мост: слушаем media:*, отправляем player_state
apps/web/src/components/DesktopBridge.tsx  связка моста с плеером
```

### Трей

Пункты: «Играть/Пауза», «Предыдущий», «Следующий», «Показать окно», «Выход».
Клик левой кнопкой по иконке показывает окно; tooltip — `Vision Audio · <трек> — <артист>`.
Подпись пункта «Играть/Пауза» меняется по состоянию плеера.

### Сворачивание в трей

Закрытие окна перехватывается (`WindowEvent::CloseRequested` → `api.prevent_close()`
+ `window.hide()`): приложение продолжает играть, пока его не закроют из меню трея.
Это ожидаемое поведение для музыкального плеера, но требует привычки: «Выход» — в трее.

### Медиа-клавиши и мост в фронтенд

| Источник | Событие | Что делает фронтенд |
| --- | --- | --- |
| `Ctrl+Alt+Space` | `media:play-pause` | `player.toggle()` |
| `Ctrl+Alt+→` | `media:next` | `player.next()` |
| `Ctrl+Alt+←` | `media:prev` | `player.prev()` |
| пункты трея | те же события | то же |
| плеер | `invoke('player_state', { playing, title, artist })` | подпись и tooltip трея |

`apps/web/src/desktop.ts` — единственное место, где фронтенд знает про Tauri:
`isDesktop()` проверяет `window.__TAURI_INTERNALS__`, поэтому в браузере и на
GitHub Pages мост выключен, а `@tauri-apps/api` подгружается динамическим импортом
(в основном бандле его нет).

Релиз `desktop-v0.3.0` (собирают CI-джобы `linux` на `ubuntu-22.04` и `windows` на
`windows-latest`):


Установка: `sudo apt install ./Vision.Audio_0.3.0_amd64.deb`, либо
`chmod +x ./Vision.Audio_0.3.0_amd64.AppImage && ./Vision.Audio_0.3.0_amd64.AppImage`,
на Windows — `.msi`/`.exe` двойным кликом.
Сервер (API) должен быть доступен — адрес задаётся на экране входа.

## Сборка

```bash
npm ci                                   # зависимости репозитория
npm --prefix apps/desktop install        # tauri CLI
npm --prefix apps/desktop run build:linux    # .deb + .AppImage
npm --prefix apps/desktop run build:windows  # .msi + NSIS (на Windows)
```

`beforeBuildCommand` собирает web (`npm --prefix ../web run build`), `frontendDist`
указывает на `apps/web/dist` — отдельной сборки фронтенда не нужно.

### CI

`.github/workflows/desktop.yml`:

- запускается на PR с изменениями `apps/desktop`, `apps/web`, `packages/shared`,
  по тегу `desktop-v*` и вручную;
- `ubuntu-22.04` + WebKitGTK 4.1 + `libayatana-appindicator3-dev` (трей) и Rust stable
  с кэшем (`Swatinem/rust-cache`);
- если компиляция падает, ошибки `error[E…]` вытаскиваются в аннотации run-а —
  так их видно без скачивания логов;
- джоба `linux` кладёт артефакт `vision-desktop-linux` (`.deb`, `.AppImage`,
  `*.AppImage.tar.gz` + `.sig` для updater), джоба `windows` — `vision-desktop-windows`
  (`.msi`, `-setup.exe`), по тегу обе публикуют GitHub Release `desktop-v<версия>`.

**Манифест обновлений из двух джоб.** `latest.json` — один файл на релиз, а платформы
собираются на разных машинах, поэтому джобы не перетирают его, а сливают: Linux
публикует манифест со своей платформой, Windows скачивает текущий (`gh release download`),
добавляет `windows-x86_64` и загружает обратно с `--clobber`. Если артефакта updater
(или подписи) нет, шаг печатает `::warning::` и выходит с кодом 0 — релиз без
автообновления лучше, чем упавшая сборка.

Релиз:

```bash
git tag desktop-v0.3.0 && git push origin desktop-v0.3.0
```

## Обновления (I4, v0.19.0)

**Как это работает.** Приложение раз в несколько часов спрашивает манифест обновлений
и, если версия новее, показывает плашку «Доступна версия X» с кнопкой «Скачать и
установить». Ничего не устанавливается молча: музыка играет, а перезапуск посреди
трека — не то, чего ждёт человек.

| Что | Где |
|---|---|
| Проверка и загрузка | `apps/web/src/updates.ts` (чистая логика) + `components/UpdateBanner.tsx` |
| Команды Rust | `updater_check`, `updater_install` в `apps/desktop/src-tauri/src/main.rs` |
| Манифест | `releases/latest/download/latest.json`, поле `updater.endpoints` в `tauri.conf.json` |
| Включение подписи | `scripts/enable-updater-signing.mjs` (шаг CI, если есть секреты) |
| Публикация | `.github/workflows/desktop.yml`, шаг «Манифест обновлений» на теге `desktop-v*` |

**Манифест** (формат Tauri updater 2):

```json
{
  "version": "0.3.0",
  "pub_date": "2026-11-11T08:00:00Z",
  "notes": "Что изменилось — первая строка CHANGELOG",
  "platforms": {
    "linux-x86_64": { "signature": "…", "url": "https://…/Vision.Audio_0.3.0_amd64.AppImage.tar.gz" },
    "windows-x86_64": { "signature": "…", "url": "https://…/Vision.Audio_0.3.0_x64-setup.nsis.zip" }
  }
}
```

Отсутствующая платформа означает «для этой системы обновления нет» — приложение это
понимает (`parseManifest` возвращает `null`), а не падает.

**Подпись.** Tauri требует, чтобы обновление было подписано ключом из
`TAURI_SIGNING_PRIVATE_KEY`; публичная часть — `plugins.updater.pubkey`. Без подписи
обновление отклоняется самим Tauri, и это правильное поведение: «отключённой проверки»
в репозитории нет.

Практическое следствие: если в `tauri.conf.json` включить `createUpdaterArtifacts`, а
`pubkey` оставить пустой, **`tauri build` падает** — в том числе на PR, где секретов нет.
Поэтому конфиг в репозитории безобиден (ни артефактов, ни ключа), а включает подпись шаг
CI:

```bash
node scripts/enable-updater-signing.mjs     # читает env, правит tauri.conf.json на месте
```

| Условие | Что делает шаг |
|---|---|
| `TAURI_SIGNING_PRIVATE_KEY` пуст | ничего, код 0 — собираются обычные установщики без обновлений |
| ключ есть, `TAURI_UPDATER_PUBKEY` пуст | код 1: подписывать ключом без публичной части бессмысленно |
| оба есть | `createUpdaterArtifacts: true` + `pubkey`, сборка выпускает `.sig` и манифест |

Секреты (ключ подписи, его пароль, публичный ключ, сертификат Windows) живут только в
GitHub Secrets; в коде и документации — имена переменных, не значения.

**Authenticode (Windows).** Установщик подписывается сертификатом из
`WINDOWS_CERTIFICATE` (base64 `.pfx`) и `WINDOWS_CERTIFICATE_PASSWORD`. Пока секретов
нет, сборка остаётся неподписанной: CI собирает установщик, а SmartScreen
предупреждает. Это осознанный компромисс — подпись без сертификата невозможна,
а «самоподписанный» сертификат хуже предупреждения, потому что учит его игнорировать.

**Проверка перед публикацией**: обновление с 0.2.0 на 0.3.0 проходит без потери
данных — библиотека живёт на сервере, в приложении только настройки (`localStorage`),
поэтому обновление их не трогает.

## Офлайн-библиотека (I5, v0.20.0)

Десктоп — это тот же web-бандл, поэтому кэш библиотеки работает и в нём, но у
приложения есть преимущество: файлы уже лежат локально, и без сети оно
запускается как обычно.

**Что происходит без сервера**

| Слой | Что даёт | Где |
|---|---|---|
| Cache Storage | звук: явно скачанные треки играют без сети | `apps/web/src/offline.ts` |
| Service worker | оболочка и последние ответы `/api/tracks`, `/api/stats` | `apps/web/public/sw.js` |
| Снимок библиотеки | список треков, плейлисты, статистика | `apps/web/src/library-cache.ts` |

Снимок — это не второй кэш «на всякий случай»: без него страница открывалась, но
показывала «Не удалось загрузить библиотеку» и пустой экран, хотя все файлы были
на диске. Теперь при ошибке сети читается последний снимок, а интерфейс говорит
правду: «Нет связи с сервером — показана сохранённая библиотека (2 часа назад)».
Кнопка в баннере — «Проверить связь», а не «Повторить»: это состояние, а не сбой.

**Решения**

- **Только чтение.** В офлайне лайк или переименование не встают в очередь на
  отправку: сервер о них не узнает, а «синхронизируем, когда появится сеть» —
  обещание, которое нельзя сдержать (трек могли удалить, `id` — смениться).
- **Снимок привязан к адресу API.** Переключили сервер с домашнего на
  `192.168.1.10` — чужой кэш не читается: показать треки другого сервера хуже,
  чем не показать ничего.
- **Не влезло — сохраняем часть.** localStorage даёт ~5 МБ; трек с волной из 320
  пиков — ~1.9 КБ, то есть 2000 треков ≈ 3.7 МБ. При переполнении снимок пишется
  в усечённом виде, а `total` помнит настоящий размер библиотеки, чтобы баннер
  сказал «сохранены первые N из M треков».
- **Запись не задерживает отрисовку**: снимок сохраняется в `requestIdleCallback`
  (с таймаутом 3 с), а не сразу после ответа API.
- **Битый снимок = нет снимка.** Ошибка разбора JSON не должна превращать
  «нет кэша» в «приложение упало».

**Проверка**

- `apps/web/src/library-cache.test.ts` — 9 тестов: чужой сервер, битый JSON,
  квота, часы назад, частичный снимок, склонения возраста.
- Замер на живой библиотеке: 100/500/1000/2000 треков занимают 0.19/0.93/1.87/3.74 МБ,
  чтение 5–85 мс; 5000 треков упираются в квоту — сохраняется 2551 с пометкой.

## Ограничения

- **Linux**: нужен `libwebkit2gtk-4.1` (Ubuntu 22.04+), в `.deb` зависимость прописана.
- **Windows**: WebView2 ставится bootstrapper-ом, установщики — `msi`/`nsis`.
- **Автообновление** проверяется раз в 6 ч; «Позже» скрывает плашку на 24 ч для этой
  версии. Установка идёт через Tauri (`passive` в Windows), перезапуск — по кнопке.
- **macOS** пока не собирается: нет Apple-подписи, код общий — джоба добавляется
  вместе с сертификатом.
- **Подпись**: Linux не требует, Windows Authenticode требует сертификат — пока
  установщик неподписанный (SmartScreen предупредит).
- Приложение — **клиент**: сервер (API + трекер реплик) остаётся отдельным
  процессом. Встроенный сид — следующий шаг (`apps/desktop/README.md`).
- **Офлайн-библиотека только для чтения**: послушать скачанное можно, менять
  библиотеку без сервера — нет (см. «Офлайн-библиотека»).
