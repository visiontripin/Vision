# Vision Server — запуск и админка (Windows + Android)

Отдельное приложение: подключиться к домашнему серверу, увидеть «что с ним», разобрать
ссылки и библиотеку. Не путать с **Vision Audio** (`apps/web`, `apps/mobile`,
`apps/desktop`) — это плеер для слушателя, а здесь инструмент владельца сервера.

Версия — **0.1.0**. Оболочка Tauri 2: окно под Windows (`.msi`/`.exe`) и APK для Android.
Тот же бандл сервер отдаёт по `/admin` — открывается с телефона в Wi-Fi без установки,
этот же адрес годится как `redirect_url` для мини-аппа Telegram.

## Что умеет

- **Подключение**: адрес сервера в любом виде (`192.168.1.10:4000`, `https://…/api`,
  с хвостовым слэшем) — приводится к рабочему виду; «сервер на этом устройстве» — для
  панели, открытой самим сервером.
- **Диагностика** (`docs/RUNBOOK.md` теми же словами, что и для человека): сервер отвечает,
  диск, применённые миграции, ffmpeg, «есть файлы без источника», задан ли `PUBLIC_URL`.
  Итог — одно из двух: «готов к работе» или «есть замечания».
- **Ссылки**: срок, открытия, комментарии; перевыпуск (новая ссылка сразу в буфере) и
  отзыв. Статистика видна только владельцу — это токен сессии, как в вебе.
- **Библиотека**: треков, занято файлами, прослушивания, жанры, сиды; быстрые переходы
  на саму библиотеку, OpenAPI и `/metrics`.

Сервер панель **не запускает**: на Android он живёт в Termux, на ПК — службой или
`npm start`. Так честнее: приложение не притворяется менеджером процессов, а проверяет
связь и объясняет, что чинить.

## Установка

| Платформа | Что взять | Откуда |
|---|---|---|
| Windows 10/11 | `Vision Server_0.1.0_x64-setup.exe` или `.msi` | GitHub Releases (`console-v*`) |
| Android 7.0+ | `vision-server-*.apk` | там же |
| Без установки | `http://<сервер>:4000/admin` | сам сервер |

Windows-сборка не подписана: при запуске SmartScreen попросит «Подробнее → Выполнить всё равно».

## Запуск из исходников

```bash
npm ci
npm run dev:console            # панель в браузере: http://localhost:5180 (API — на :4000)
npm --prefix apps/console run tauri dev        # окно Windows
npm --prefix apps/console run build:windows    # установщик .msi/.exe
npm --prefix apps/console run build:android    # APK (нужны NDK и Rust targets)
```

Требования для Tauri: Rust stable, на Windows — MSVC Build Tools и WebView2 (ставится сам),
для Android — JDK 17 + Android SDK/NDK, для Linux — `libwebkit2gtk-4.1-dev`.

## Сборка в CI

`.github/workflows/console.yml`:

- `check` — типы, тесты чистой логики, сборка панели и тест, что сервер отдаёт `/admin`
  (на каждом PR);
- `windows` — установщик `.msi` + `.exe` (artifact `vision-server-windows`);
- `android` — APK через `tauri android build` (artifact `vision-server-android`),
  джоба помечена `continue-on-error: true`: это отдельный канал поставки и её падение
  не блокирует PR. Чтобы причина была видна без доступа к логам, шаги сборки пишут
  ошибки аннотациями (`::error::…`), а перед сборкой печатается окружение Android;
- тег `console-v*` — те же артефакты уезжают в GitHub Release.

Иконки для оболочки генерируются без зависимостей: `node scripts/make-icons.mjs`
(пишет PNG-набор и `icon.ico` в `src-tauri/icons/`). `.ico` обязателен — без него
`tauri-build` на Windows падает на этапе сборки, ещё до компиляции.

## Структура

```
src/api.ts       контракт панели: адрес, вход, /api/health, ссылки, статистика
src/lib.ts       чистая логика: размеры, время, диагностика (под тестами)
src/App.tsx      экраны: подключение → диагностика → ссылки → библиотека
src-tauri/       Rust-оболочка: окно Windows, команда platform(), capabilities
```

Права Tauri минимальные: только `core:default` и собственная команда `platform()` —
ни файлов, ни shell. CSP панели: `default-src 'self'`, запросы только к своему origin
(или явно введённому адресу — это отдельная установка, браузерных ограничений у неё нет).
