# Vision Audio — Android и iOS

React Native (Expo) + общий клиент `@vision/shared`. Отдельный проект: не входит
в npm workspaces корня, чтобы не тянуть 400 МБ зависимостей при обычной сборке веба.

Версия клиента — **0.7.0**. Работает в Expo Go (SDK 54).

## Как это устроено: телефон — самостоятельный плеер

С 0.7.0 приложение не требует сервера. Библиотека (файлы, плейлисты, статистика)
хранится на устройстве, плеер открывается сразу — без адреса, пароля и сети.
Подключение к домашнему серверу осталось, но стало **необязательным** вторым
источником: «＋» → «Домашний сервер». См. `docs/adr/0010-phone-library-first.md`.

| Что | Где |
| --- | --- |
| Ядро библиотеки (без React Native) | `src/lib/local.ts` |
| Хранилище на устройстве + импорт | `src/local.tsx` |
| Разбор ссылок и перехватчик звука | `src/lib/link.ts` |
| Экран «по ссылке» | `src/screens/LinkImportScreen.tsx` |
| Необязательный сервер, статистика | `src/screens/ServerScreen.tsx` |

## Готовая APK и ссылка

Ставить ничего не нужно — установочный файл собирается в CI и лежит в релизах:

```
https://github.com/visiontripin/Vision/releases/latest
прямая ссылка на актуальную сборку (не меняется от версии к версии):
https://github.com/visiontripin/Vision/releases/latest/download/VisionAudio-latest.apk
```

- Нужен Android 7.0+ (`minSdk 24`), файл универсальный (все ABI), ~57 МБ.
- Скачать `.apk` на телефон → «Установить из неизвестного источника»
  (Chrome: «Всё равно скачать» — это нормально для самоподписанного APK).
- Открыть приложение и нажать «＋ Добавить файлы» — музыка с телефона появится в
  библиотеке. Адрес сервера нужен только тем, у кого есть своя библиотека на ПК.
- Рядом лежит `<файл>.apk.sha256` для проверки целостности.
- Обновление: скачать новую APK с той же страницы и установить поверх —
  ключ подписи постоянный, вход и офлайн-копии сохраняются.

Пересобрать: Actions → **Android APK** → Run workflow (или `git tag android-v0.2.0`
+ push). Подробности, ключ подписи и ручная сборка — `docs/ANDROID.md`.

## Что уже умеет

- **Библиотека на телефоне**: файлы с устройства (несколько за раз), поиск по
  названию/исполнителю/жанру, размер библиотеки в шапке. Повторный импорт не
  задваивает треки.
- **По ссылке**: прямой аудиофайл скачивается в папку приложения; страница
  открывается во встроенном браузере, звук находится автоматически.
- **Плейлисты**: на устройстве; долгое нажатие на треке → «В плейлист…» (меню
  системное, его не срезает край списка).
- **Статистика**: минуты за неделю и топ треков — экран в настройках. Считается
  реально прослушанное время.
- **Сервер (необязательно)**: адрес и пароль домашнего сервера, проверка
  соединения. Ошибка соединения не мешает локальной музыке.
- **Плеер**: тап по мини-плееру разворачивает экран на весь экран — обложка фоном,
  **волна трека** (вместо полосы прогресса) с перемоткой пальцем и временем под пальцем,
  крупное название, круглые shuffle/prev/play/next/repeat, ±15 с, скачивание.
  Геометрия волны (`src/lib/wave.ts`) покрыта тестами, сторонних слайдеров нет.
  Фон при выключенном экране (`staysActiveInBackground` + `UIBackgroundModes: audio` /
  foreground service).
- **Офлайн**: файлы на телефоне играют без сети всегда. Копии с сервера
  (кнопка ↓) лежат в приватном каталоге приложения; «Настройки» показывают
  занятое место и позволяют удалить копию.
- **Настройки**: смена сервера с проверкой, выход, управление копиями.

Проверка контракта с сервером (Node + tsx, без эмулятора): `scripts`-скрипт
прогоняет вход → треки → плейлисты → media → скачивание → Range-стрим → play/listen.

## Запуск

```bash
cd apps/mobile
npm install
npx expo install --fix        # выравнивает версии под вашу версию Expo SDK
npx expo start                # QR в Expo Go на телефоне
```

Адрес сервера задаётся либо на экране входа, либо переменной окружения:

```bash
EXPO_PUBLIC_API_URL=http://192.168.1.10:4000 npx expo start   # телефон в той же Wi-Fi
EXPO_PUBLIC_API_URL=http://10.0.2.2:4000 npm run android      # эмулятор Android
EXPO_PUBLIC_API_URL=http://localhost:4000 npm run ios         # симулятор iOS
```

Сервер (Termux/ПК) должен слушать `0.0.0.0` — по умолчанию так и есть. Если телефон
не дома, используйте адрес Tailscale (`https://<device>.<tailnet>.ts.net`).

## Сборки

**APK для установки на телефон** — CI, без Expo-аккаунта (рекомендуется):

```bash
gh workflow run android.yml            # → Release android-v<версия> с .apk
# или вручную на машине с JDK 17 + Android SDK:
npx expo prebuild --platform android --no-install
node ../../scripts/android-prepare.mjs && (cd android && ./gradlew assembleRelease)
```

**EAS** (нужен аккаунт Expo; AAB для Google Play / IPA для TestFlight):

```bash
npm i -g eas-cli && eas login
eas build:configure
npm run build:android
npm run build:ios
```

## Реплики в трекере (v0.9.0)

Скачанный трек объявляется в реестре реплик как `mobile` — «копия есть у телефона».
Раздавать по HTTP телефон не может (нет локального сервера, ОС убивает фоновые
процессы), поэтому мобильная копия не считается источником: библиотека показывает
число устройств с файлом, а скачивание идёт с origin/Termux/ПК.

- объявление — при завершении скачивания, снятие — при удалении копии;
- `hash` (sha256) хранится в индексе копий, поэтому снятие работает и после
  перезапуска приложения;
- всё best-effort: без сети трекер просто не обновится, скачивание не страдает.

Модель целиком — `docs/DISTRIBUTED.md`.

## Ограничения текущей версии

- **Экран блокировки и Bluetooth-гарнитура**: `expo-av` не даёт системные
  медиа-кнопки. Нужен dev build с `react-native-track-player` (следующая итерация).
- **Загрузка с телефона** (upload) пока только через веб-версию.
- **Сидирование файлов другим пользователям** — отдельная итерация: план в
  `docs/DISTRIBUTED.md` (контент-адресация, реестр реплик, сиды Termux/десктоп/телефон).
