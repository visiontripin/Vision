## 0.12.0 — 2026-11-10

Фаза 6, шаг 1: библиотекой можно поделиться, не открывая её целиком. Приватная ссылка
на трек или плейлист открывается у друга без пароля, живёт заданный срок, отзывается
одной кнопкой и разворачивается в мессенджере карточкой с обложкой.

### Приватные ссылки (E1) — `docs/adr/0007-private-links.md`

- **Модель**: `shares` + `share_hits` (миграция `008-shares`). В базе лежит
  `sha256(token)`, сам токен показывается один раз — дамп БД не даёт рабочий URL.
  Перевыпуск сохраняет старый хеш в `prev_token_hash`, поэтому старая ссылка отвечает
  `410 rotated` («ссылка перевыпущена»), а не `404`.
- **API**: `POST /api/shares` (targetKind, targetId, title, ttl, maxPlays),
  `GET /api/shares?targetKind=&targetId=&includeRevoked=1`, `GET/PATCH/DELETE /api/shares/:id`
  (`?purge=1` — удалить запись и журнал), `POST /api/shares/:id/rotate`. TTL: `30m`…`30d`,
  `forever`; по умолчанию 7 дней (`SHARE_DEFAULT_TTL_MS`), максимум год.
- **Гостевой доступ** (`/s/*`, без сессии и без токена): страница, `stream` с Range
  (`200/206/HEAD`, `302` на живой сид, `409 no_source`), `download` с
  `Content-Disposition`, `cover` для OG. Ссылка на трек отдаёт только этот трек,
  ссылка на плейлист — только треки плейлиста (`403` на остальное), то есть IDOR
  невозможен по построению.
- **Лимит открытий** считает показы страницы; Range-запросы и скачивания пишутся только
  в журнал — браузер с десятком запросов не съедает лимит и не раздувает статистику.
- **Приватность гостя**: `share_hits` хранит `sha256(secret + ip)`, а не IP; владелец
  видит «сколько разных людей открыло», PII в БД и логах нет.
- **Токен не течёт**: структурные логи пишут `/s/:token/...` вместо реального токена
  (иначе лог-агрегатор превращается в список рабочих ссылок), гостевые ответы идут с
  `Referrer-Policy: no-referrer` и `Cache-Control: no-store`.
- **Удаление** трека или плейлиста отзывает все его ссылки в той же операции.
- Метрики: `vision_share_created_total{kind}`, `vision_share_open_total{kind}`,
  `vision_share_revoked_total`, `vision_share_rotated_total`.

### Публичная страница с OG-превью (E2)

- SSR-HTML без JavaScript и без бандла: нативный `<audio controls>` (Range работает сам),
  список треков плейлиста, кнопка «Скачать», адаптив до 360 px, тёмная тема как в приложении.
- OG-теги `og:type=music.song|music.playlist`, `og:title`, `og:description`, `og:url`,
  `og:image` (из обложки трека) — карточка корректно разворачивается в Telegram/WhatsApp.
- Страница закрыта от поисковиков (`X-Robots-Tag: noindex`, `<meta name="robots">`) и
  отдаётся с CSP `default-src 'none'; media-src 'self'` — без сторонних запросов.
- Человеческие состояния `410`: «отозвана», «перевыпущена», «истёк срок», «лимит открытий».

### Веб-интерфейс (FE/UX)

- Меню трека → **«Поделиться ссылкой»**: подпись для себя, срок жизни, лимит открытий,

## 0.10.1 — 2026-11-09

Офлайн-копии адресуются содержимым, а не строкой трека. Продолжение этапа 3: клиенты
и сервер понимают «файл» одинаково — по `sha256`.

### Что изменилось

- **Веб (`apps/web/src/offline.ts`)**: ключ копии в Cache Storage —
  `/__vision-offline/<checksum>` (у треков без `checksum` остаётся `/__vision-offline/<id>`).
  Индекс `vision.offline.index` получил поле `hash`, а поиск идёт по любому из двух
  ключей: `id` или `sha256`. Один файл, импортированный заново под новым `id`, не
  качается второй раз; удаление и воспроизведение находят копию по обоим ключам.
  Новые хелперы `offlineRef(track)` (ключ копии), `isTrackCached`, `offlinePlayable`,
  `removeTrackCopy` — компоненты работают с треком, а не с сырыми ключами.
- **Совместимость**: копия, скачанная до появления трекера (ключ `/__vision-offline/<id>`),
  по-прежнему находится по `checksum`; повторное скачивание переводит её на контентный
  ключ и удаляет старую запись из Cache Storage.
- **Веб-вызовы**: `TrackList`, `state/player.tsx`, `App.tsx`/`seeds.ts` (`syncReplicas`)
  работают через `isTrackCached` / `offlinePlayable` / `removeTrackCopy`, а не с `track.id`.
- **Телефон (`apps/mobile/src/downloads.tsx`)**: индекс копий ищет запись по `id` или
  по `hash` (`apps/mobile/src/lib/downloads.ts`, чистая функция `findCopy`); повторное
  скачивание того же содержимого пропускается, удаление работает по любому ключу.
  Имена файлов не меняются — старые загрузки и записи без `hash` продолжают работать.
- Совместимость: старый индекс без `hash` читается как раньше, переиндексация не нужна.

### Тесты и документация

- `apps/web/src/offline.cache.test.ts`: «копия адресуется sha256 — другой id того же
  файла не качается второй раз» (проверяется и реальный ключ в Cache Storage) и

- `apps/web/src/offline.test.ts`: проверка `offlineRef`.

- `npm run test:local` — **43/43**, `npm test` — 36/36, `build`, `build:pages`,

## 0.10.0 — 2026-11-09

Фаза 3, завершение этапа «трекер и сиды»: копиями можно управлять руками прямо из
интерфейса, а не только через API.

### Управление репликами

- **`DELETE /api/blobs/:hash/replica`** (`services/api`): убирает файл именно из каталога
  сида и снимает свой сид с реестра трекера; origin-файлы в хранилище и чужие сиды не
  трогает. Ответы `204` / `404 not_a_replica`; метрика `vision_blob_replica_removed_total`.
- **`GET /api/blobs/:hash`** теперь отдаёт `seeded` (файл лежит в `SEED_DIR` этого узла,
  его можно раздать) и `deviceId` (кто этот узел по мнению трекера).
- **`services/api/src/seeds.js`**: `replicaFileFor` (поиск файла реплики с учётом mime),
  `dropReplica` (rm файла + `DELETE FROM blob_seeds WHERE device_id = <свой>`),
  `invalidateSeedCache` — после репликации кэш листинга каталога сбрасывается, иначе
  `seeded` и `/seed/:hash` врут в течение двух секунд.
- **Веб: экран «Источники файла»** (`apps/web/src/components/SourcesModal.tsx`) — меню
  трека → «Источники файла» (иконка и число устройств). Показывает факты (локально,
  сколько раздают, сколько копий, размер), список сидов с видом устройства и точкой
  «online», кнопку **«Забрать копию сюда»** (`POST /api/blobs/:hash/replicate`) и
  **«Удалить реплику»** (`DELETE /api/blobs/:hash/replica`, с подтверждением). После
  действия библиотека перезагружается. В локальном режиме (`VITE_LOCAL_MODE`) экран
  не рендерится — трекера там нет.
- **`@vision/shared`**: `BlobState.seeded`, `BlobState.deviceId`, метод
  `api.removeReplica(hash)`.
- **Телефон**: трек `available: false` без скачанной копии помечается оранжевым и
  «· нет источника», тап по нему показывает «Нет источника» вместо молчаливой ошибки.

### Тесты и документация

- `services/api/test/seeds.test.js` — 12 сценариев на двух живых узлах: добавлены
  «удаление реплики: файл уходит, трек снова качается с пира» и «удаление не-реплики
  (origin-файл) запрещено»; сценарий снятия сида теперь проверяет и `409 no_source`
  после исчезновения последней копии. Всего `npm test` — 36/36, `npm run test:local` — 35/35.
- **OpenAPI**: маршрут `DELETE /blobs/{hash}/replica`, описание `seeded`/`deviceId`.
- `docs/API.md`, `docs/DISTRIBUTED.md` (ручное управление копиями, этап 3 закрыт),
  `docs/IMPROVEMENTS.md`, `README.md`.

## 0.9.0 — 2026-11-09

Фаза 3, этап «трекер и сиды»: сервер перестаёт быть хранилищем. Файл адресуется
по `sha256`, сервер держит реестр реплик и выдаёт подписанные ссылки на устройства.

### Трекер реплик (`services/api`)

- **Миграция `007-blobs`**: таблицы `blobs` (hash, bytes, mime) и `blob_seeds`
  (device_id, kind, base_url, servable, online_at); существующие треки сразу
  становятся блобами по `tracks.checksum`.
- **`services/api/src/seeds.js`** — вся логика: объявление блобов, heartbeat сидов,
  сводка «есть у кого», порядок предпочтения (origin → node → desktop → mobile →
  browser), подписанные ссылки, локальное наличие файла, репликация.
- **`GET /seed/:hash?exp&sig`** — отдача файла устройством: Range, ETag, HEAD,
  401 без подписи, 403 при `SEED_ENABLED=0`. Подпись общая для узлов роя.
- **`GET /api/tracks/:id/download`** — 302 на живое устройство (или свой `/seed`),
  `409 no_source`, если файл сейчас никто не раздаёт; `?json=1` — адрес и список сидов.
- **`POST /api/blobs`, `GET /api/blobs/:hash`, `/seeds`, `/seed` (heartbeat / снятие),
  `/replicate`** — реестр и репликация с проверкой `sha256` после скачивания.
- **`STORAGE_MODE=metadata`**: `POST /api/tracks` с JSON принимает только метаданные
  (`hash`, `bytes`, `mime`, `duration`, `peaks`) и адрес сида; файл остаётся у загрузившего.
- **Треки в выдаче** (`/api/tracks`, `/api/tracks/:id`, плейлисты, история) получают
  `checksum`, `sources { local, servable, replicas, devices, kinds }` и `available`.
- **`/api/media`**: если файла на узле нет, но есть живой сид, `stream` указывает на

## 0.6.0 — 2026-11-09

Фаза 2 «Аудио 2.0»: лёгкий поток, ровная громкость, HLS и прогрев следующего трека.

### Добавлено

- **Фоновый транскодинг** (`services/api/src/transcode.js`): после загрузки трек
  попадает в очередь и перекодируется в **opus 96 kbps** и **aac 128 kbps**, плюс
  **HLS-нарезка** по 6 секунд. Очередь последовательная, ответ клиенту ffmpeg не ждёт.
- **Нормализация −14 LUFS** (`loudnorm=I=-14:TP=-1.5:LRA=11`) при каждом варианте —
  треки из разных источников звучат на одном уровне.
- **`GET /api/tracks/:id/stream?format=opus|aac`** — отдача варианта с Range; если его
  ещё нет, сервер прозрачно отдаёт оригинал (`X-Variant-Fallback`).
- **HLS**: `GET /api/tracks/:id/hls.m3u8` и `GET /api/tracks/:id/hls/:segment`.
  Сегменты в плейлисте переписаны в абсолютные пути с той же HMAC-подписью, поэтому
  относительное разрешение URL не ломает авторизацию.
- **`GET /api/media`** теперь отдаёт `streams: { original, opus, aac }` и `hls`;
  `GET /api/tracks/:id` — список готовых `variants`.
- **Выбор кодека на клиенте** через `canPlayType()`: opus → aac → оригинал, а в Safari
  с нативным HLS — плейлист.
- **Prefetch следующего трека**: подписанная ссылка запрашивается заранее, первые
  256 КБ уходят в HTTP-кэш браузера — переключение почти без буферизации.
- **320 пиков вместо 180** + сглаживание волны (среднее по окну и 3-точечный фильтр),
  чтобы не было «дребезга» на тихих участках.
- Метрики `vision_transcode_total{result}` и `vision_transcode_seconds_total{kind}`;
  `/api/health` показывает `ffmpeg` и `transcode`.
- `TRANSCODE_BACKFILL=1` — при старте догоняет треки, загруженные до появления ffmpeg.

### Важно

- **Без ffmpeg сервис работает как раньше**: оригиналы, без вариантов и HLS.
  Бинарник ищется в `FFMPEG_PATH` → `ffmpeg-static` → `PATH`; в Docker-образ
  добавлен `apk add ffmpeg`.
- `ffmpeg-static` подключён в `optionalDependencies`: если бинарник не скачался
  (нет сети/неподходящая платформа), `npm install` не падает.
- Осталось на потом: MSE-плеер для HLS в Chrome/Firefox (сейчас HLS играет в Safari),
  gapless/кроссфейд, кэш медиа в Cache Storage.

  `busy_timeout=5000`.
- Веб-клиент: поиск через сервер (FTS) с дебаунсом и общим числом результатов,
  размер медиатеки в статистике, мобильный прогресс-бар с перетаскиванием и
  safe-area отступы, кэш подписанных ссылок с фоновым обновлением.

### Изменено

- Контракт API: `GET /api/tracks` принимает `offset` и `sort=relevance`,
  `GET /api/stats` отдаёт `bytes` и `migrations`.
- `packages/shared`: `media()`, `tracksPage()`, `listen()`, `history()`;
  `streamUrl()`/`coverUrl()` удалены — вместо них подписанные ссылки.
- Тестов API стало 14: подписи, Range/416, дедуп, FTS, история, плейлисты,
  метрики и заголовки безопасности.

### Ограничения версии

- Транскодирования всё ещё нет (Фаза 2): отдаётся оригинальный файл.
- `/api/v1` и OpenAPI-схема не сделаны — контракт описан в `docs/API.md`.
- Мобильное и десктопное приложения не пересобирались (нет устройства/Rust в CI).
