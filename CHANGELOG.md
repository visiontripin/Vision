# Changelog

## 0.8.1 — 2026-11-09

Готовый APK приложения для Android со ссылкой на скачивание — без Expo-аккаунта
и без локального Android SDK.

### Сборка

- **`.github/workflows/android.yml`**: `npm ci` → `tsc` → `expo prebuild` →
  `scripts/android-prepare.mjs` → `gradlew assembleRelease` → артефакт
  `VisionAudio-<версия>-android.apk` (+ `.sha256`) и GitHub Release `android-v<версия>`.
  Запуск: Actions → «Android APK» → Run workflow, либо тег `android-v*`.
- **`scripts/android-prepare.mjs`**: патчит сгенерированный `build.gradle` —
  `versionCode` из `GITHUB_RUN_NUMBER` (обновления ставятся поверх), `versionName`
  из `app.json`, signingConfig `visionRelease` (PKCS#12).
- **Ключ подписи** `apps/mobile/vision-release.p12` (самоподписанный, alias
  `vision`) зафиксирован в репозитории, чтобы каждая сборка имела одинаковую
  подпись; переменные `VISION_KEYSTORE_*` позволяют заменить его на секреты.
- **Иконки**: `scripts/make-icons.mjs` теперь рисует и ассеты мобильного проекта —
  `apps/mobile/assets/{icon,adaptive-icon,splash-icon}.png` (1024², adaptive icon
  с прозрачным фоном); `app.json` получил `icon`, `adaptiveIcon.foregroundImage`,
  `splash.image`, `android.versionCode`.
- **`usesCleartextTraffic`**: релизная сборка Android блокирует `http://`, поэтому
  добавлены `expo-build-properties` (`android.usesCleartextTraffic: true`) и
  `expo-system-ui` (тёмная тема без мигания); `android-prepare.mjs` проверяет
  атрибут в манифесте и патчит его сам, если плагин не сработал.
- **Проверка перед публикацией**: `apksigner verify --print-certs`, `aapt2 dump
  badging` (package/version/ABI), наличие `assets/index.android.bundle`; результаты —
  аннотациями на странице job-а. Сборка не публикуется, если подпись не подтверждена.
- `apps/mobile/android`, `ios`, `dist` — в `.gitignore` (генерируются prebuild-ом).

### Документация

- **`docs/ANDROID.md`** — как устроена сборка, подпись и её оговорки, установка
  на телефон, проверка SHA-256, ручная сборка, ограничения.
- `apps/mobile/README.md` — раздел «Готовая APK и ссылка».
- Первый релиз: `android-v0.2.0` — `VisionAudio-0.2.0-android.apk` (57 МБ,
  `Verifies`/v2, `package app.vision.audio`, targetSdk 36, versionCode 5).

## 0.8.0 — 2026-11-10

Фаза 3: мобильное приложение (Android/iOS) — вход, библиотека, плейлисты, плеер
с фоном и офлайн-копиями. Плюс план распределённого хранения (трекер + сиды).

### Мобильный клиент 0.2.0 (`apps/mobile`)

- **Вход с настраиваемым адресом сервера**: адрес домашнего сервера (Wi-Fi,
  Tailscale, туннель) вводится на экране входа и запоминается; меняется в настройках
  с проверкой `GET /api/me`.
- **Библиотека**: обложки, поиск по названию/исполнителю/жанру/альбому,
  pull-to-refresh, индикатор офлайн-копий в шапке.
- **Плейлисты**: список, состав, «Играть», «Скачать плейлист» с прогрессом.
- **Плеер** (`expo-av`): очередь, следующий/предыдущий, перемешивание, повтор
  (все/один), перемотка тапом по полосе, ±15 с, фоновое воспроизведение
  (`staysActiveInBackground`, `UIBackgroundModes: audio`, foreground service).
- **Офлайн-копии** (`expo-file-system`): файл качается в приватный каталог,
  играет без сети; AAC предпочитается (его понимают и AVPlayer, и ExoPlayer),
  расширение выводится из MIME; индекс в AsyncStorage, пропавшие файлы вычищаются.
- **Настройки**: адрес сервера, выход, список копий с размерами, очистка, занятое место.
- 13 новых юнит-тестов (`format`, `queue`, `media`), `tsc --noEmit` для мобильного
  проекта, проверка контракта с живым сервером (вход → треки → медиа → скачивание →
  Range-стрим → play/listen).

### Документация

- `apps/mobile/README.md` — запуск в Expo Go, переменные, сборки, ограничения.
- **`docs/DISTRIBUTED.md`** — план «трекер + сиды» под выбор пользователя
  (несколько сидов: Termux + десктоп + телефон): контент-адресация по SHA-256,
  реестр реплик, политика «нет источника», почему WebRTC/TURN отложены.

### Ограничения

- Экран блокировки (медиа-кнопки) требует dev build с `react-native-track-player`.
- Загрузка с телефона — пока только веб-версия.
- Сидирование файлов другим — следующая итерация (`docs/DISTRIBUTED.md`).

## 0.7.0 — 2026-11-10

PWA и офлайн-копии: библиотека открывается без сети, явно скачанные треки играют
без интернета.

### Добавлено

- **PWA-манифест и service worker**: приложение ставится на домашний экран
  (Android/iOS/десктоп), оболочка (`index.html`, ассеты, иконки) и ответы
  `/api/tracks`, `/api/playlists`, `/api/history`, `/api/stats` кэшируются —
  при пропаже сети открывается библиотека, а не ошибка браузера.
- **Офлайн-копии треков**: в меню трека появился пункт «Скачать офлайн»
  (с прогрессом), копия кладётся в Cache Storage, в списке есть метка. Плеер
  автоматически играет копию вместо сети — без запросов и трафика; подписанные
  ссылки при этом не нужны (у копии синтетический ключ `/__vision-offline/<id>`).
- **Лимит офлайн-кэша** (по умолчанию 512 МБ) с вытеснением самых старых копий,
  настройка лимита и полная очистка в разделе «Статистика».
- **Иконки и манифест генерируются скриптом** `scripts/make-icons.mjs` (без
  зависимостей, PNG пишется через zlib) — `npm run icons`.
- CSP дополнен `worker-src`/`manifest-src`, отдача `.webmanifest` с правильным
  `Content-Type`.

### Важно

- Кэш браузера доступен только в защищённом контексте: **HTTPS или localhost**.
  На `http://192.168.x.x` (Termux в домашней сети) офлайн-кнопки не показываются —
  это ограничение браузера, а не приложения; через Tailscale/Cloudflare всё работает.
- Service worker регистрируется только в production-сборке; dev-сервер не кэширует.

### Исправлено

- Тест поймал баг вытеснения: вытесненная копия удалялась из Cache Storage, но
  возвращалась в индекс при записи новой — теперь индекс и кэш не расходятся.

## 0.6.1 — 2026-11-09

Подготовка к домашнему серверу на Android (Termux) и починка резолва ffmpeg.

### Исправлено

- **Резолв ffmpeg теперь проверяет запуск, а не наличие файла.** `ffmpeg-static`
  на Android/Termux ставится как glibc-бинарник, который не запускается; раньше
  сервис выбирал его по `existsSync` и молча оставался без транскодинга при живом
  `ffmpeg` в `PATH`. Теперь кандидаты (`FFMPEG_PATH` → `ffmpeg-static` → `PATH`)
  пробуются по очереди до первого рабочего.

### Добавлено

- **Экономный профиль на Android**: `process.platform === 'android'` (или
  `TERMUX_VERSION`) включает только opus, выключает HLS и ограничивает ffmpeg
  двумя потоками. Всё переопределяется `TRANSCODE_CODECS`, `HLS_ENABLED`,
  `FFMPEG_THREADS`.
- **`FFMPEG_THREADS`** — ограничение потоков ffmpeg (полезно и на слабых серверах).
- **`scripts/termux-setup.sh`** — установка `nodejs`/`ffmpeg`/`git`, сборка web,
  каталог данных, автозапуск через Termux:Boot с `termux-wake-lock`.
- **`docs/TERMUX.md`** — установка, доступ по Wi-Fi, HTTPS через Tailscale/Cloudflare
  Tunnel, автозапуск, обновление, бэкап и таблица типовых проблем.
- **Понятные ошибки старта** (`services/api/src/start.js`): вместо стека — подсказка
  про `node:sqlite`, занятый порт и права на `/sdcard`. `npm start` и Docker
  используют его как точку входа.
- `/api/health` отдаёт `runtime` (platform/arch/node/termux), `ffmpeg.path` и
  `transcode.settings`.
- 4 юнит-теста на резолв ffmpeg: приоритет `FFMPEG_PATH`, пропуск нерабочего
  бинарника, полное отсутствие ffmpeg, Android-профиль потоков.

## 0.6.0 — 2026-11-09

Фаза 2 «Аудио 2.0»: лёгкий поток, ровная громкость, HLS и прогрев следующего трека.

### Добавлено

- **Фоновый транскодинг** (`services/api/src/transcode.js`): после загрузки трек
  попадает в очередь и перекодируется в **opus 96 kbps** и **aac 128 kbps**, плюс
  **HLS-нарезка** по 6 секунд. Очередь последовательная, ответ клиенту ffmpeg не ждёт.
- **Нормализация −14 LUFS** (`loudnorm=I=-14:TP=-1.5:LRA=11`) при каждом варианте —
  треки из разных источников звучат на одном уровне.
- **`GET /api/tracks/:id/stream?format=opus|aac`** — отдача варианта с Range; если его
  ещё нет, сервер прозрачно отдаёт оригинал (`X-Variant-Fallback`).
- **HLS**: `GET /api/tracks/:id/hls.m3u8` и `GET /api/tracks/:id/hls/:segment`.
  Сегменты в плейлисте переписаны в абсолютные пути с той же HMAC-подписью, поэтому
  относительное разрешение URL не ломает авторизацию.
- **`GET /api/media`** теперь отдаёт `streams: { original, opus, aac }` и `hls`;
  `GET /api/tracks/:id` — список готовых `variants`.
- **Выбор кодека на клиенте** через `canPlayType()`: opus → aac → оригинал, а в Safari
  с нативным HLS — плейлист.
- **Prefetch следующего трека**: подписанная ссылка запрашивается заранее, первые
  256 КБ уходят в HTTP-кэш браузера — переключение почти без буферизации.
- **320 пиков вместо 180** + сглаживание волны (среднее по окну и 3-точечный фильтр),
  чтобы не было «дребезга» на тихих участках.
- Метрики `vision_transcode_total{result}` и `vision_transcode_seconds_total{kind}`;
  `/api/health` показывает `ffmpeg` и `transcode`.
- `TRANSCODE_BACKFILL=1` — при старте догоняет треки, загруженные до появления ffmpeg.

### Важно

- **Без ffmpeg сервис работает как раньше**: оригиналы, без вариантов и HLS.
  Бинарник ищется в `FFMPEG_PATH` → `ffmpeg-static` → `PATH`; в Docker-образ
  добавлен `apk add ffmpeg`.
- `ffmpeg-static` подключён в `optionalDependencies`: если бинарник не скачался
  (нет сети/неподходящая платформа), `npm install` не падает.
- Осталось на потом: MSE-плеер для HLS в Chrome/Firefox (сейчас HLS играет в Safari),
  gapless/кроссфейд, кэш медиа в Cache Storage.

## 0.5.0 — 2026-11-10

Массовый импорт: папка целиком, ZIP-архив и список ссылок SoundCloud из файла.

### Добавлено

- **Импорт папки** — кнопка «Папка» (`webkitdirectory`) и перетаскивание каталога
  с рекурсивным обходом через `webkitGetAsEntry`.
- **Импорт ZIP без зависимостей** — свой парсер центрального каталога и
  распаковка `deflate` через встроенный `DecompressionStream('deflate-raw')`.
  Служебные файлы (`__MACOSX/`, `._*`, `.DS_Store`), картинки и текст
  отбрасываются; ZIP64 и шифрованные архивы пропускаются, не ломая импорт.
- **Отчёт по очереди**: загружено / дубликатов / ошибок, прогресс по каждому файлу,
  понятный статус «уже в библиотеке» для 409 от API.
- **Импорт списка ссылок SoundCloud** из `.txt`/`.csv` — ссылки вытаскиваются
  регуляркой и уходят пачками по 50.
- Анализ аудио (длительность + пики) вынесен в `apps/web/src/audio.ts` и
  переиспользуется одиночной и массовой загрузкой.
- Разбор имён: «01 - Track.mp3» больше не делает «01» исполнителем, а папка
  «Artist - Album/» из архива подсказывает исполнителя.

### Изменено

- `npm run test:local` теперь гоняет 12 тестов: IndexedDB-клиент (3), разбор имён
  файлов (3), ZIP-парсер и подсказки исполнителя (6).
- `tsconfig` веб-клиента разрешает импорт с расширением `.ts` (нужно тестам).

## 0.3.0 — 2026-11-10

Завершение Фазы 1: стабильный версионированный контракт и виртуализация списка.

### Добавлено

- **`/api/v1/*`** — версионированный алиас контракта (`/api/*` продолжает работать).
  Внутри маршруты описаны один раз; версия живёт в пути и в `/api/health`.
- **OpenAPI 3.1** — `GET /api/v1/openapi.json` (без токена). Схема лежит рядом с
  кодом (`services/api/src/openapi.js`): все маршруты, схемы Track/Playlist/
  HistoryEntry/Stats/MediaItem/Error, security-схемы bearer + медиа-подпись.
- **Виртуализация списка треков** без зависимостей: при > 120 записях рисуется
  окно ±8 строк, высота строки измеряется по факту (`getBoundingClientRect`),
  `aria-posinset` / `aria-setsize` сохраняют семантику для скринридеров.
  Библиотека на 5 000 треков держит в DOM ~30 узлов вместо 5 000.

### Изменено

- Метрики лейблят маршруты канонически (`/api/v1/tracks` → `/api/tracks`),
  чтобы дашборды не расщеплялись на два ряда.
- Тестов API стало 16 (добавлены схема и v1-алиас).

## 0.2.0 — 2026-11-10

Фаза 1 «Прод-готовность веба»: поиск, метаданные, безопасные медиа-ссылки,
наблюдаемость и «Продолжить слушать».

### Добавлено

- **FTS5-поиск** (`unicode61 remove_diacritics 2`) по названию, артисту, альбому,
  жанру и описанию с префиксным совпадением, сортировками
  (`relevance|recent|oldest|title|plays|duration`), `limit/offset` и `X-Total-Count`.
  Индекс синхронизируется триггерами и в транзакциях правки/удаления.
- **Миграции БД** с таблицей `schema_version`: `001-base`, `002-fulltext-search`,
  `003-checksum` (уникальный частичный индекс), `004-listens`. Идемпотентны,
  применяются при старте, статус виден в `/api/health`.
- **Теги и обложки из файлов** — собственный парсер без зависимостей: ID3v2.3/2.4
  (включая APIC), FLAC Vorbis comments + PICTURE, WAV `LIST/INFO` и `id3 `-чанк,
  Ogg/Opus, MP4 `ilst`, ID3v1 в хвосте. Лимит обложки 5 МБ, ошибки парсинга не
  ломают загрузку.
- **Подписанные медиа-URL**: `GET /api/media?ids=` выдаёт HMAC-SHA256 ссылки на
  поток и обложку с TTL (`MEDIA_URL_TTL_MS`). Токен больше не попадает в URL —
  `?token=` удалён.
- **Дедупликация по SHA-256** при загрузке: `409 duplicate` + существующий трек.
- **История прослушиваний** (`/listen`, `/api/history`) и блок «Продолжить слушать»
  в веб-клиенте: карточки с позицией, запуск с того же места.
- **Наблюдаемость**: `/metrics` в формате Prometheus (счётчики, гистограмма
  задержек, gauge по библиотеке), структурные JSON-логи с `X-Request-Id`,
  security-заголовки и CSP.
- **Надёжность SQLite**: WAL, `synchronous=NORMAL`, `foreign_keys=ON`,
  `busy_timeout=5000`.
- Веб-клиент: поиск через сервер (FTS) с дебаунсом и общим числом результатов,
  размер медиатеки в статистике, мобильный прогресс-бар с перетаскиванием и
  safe-area отступы, кэш подписанных ссылок с фоновым обновлением.

### Изменено

- Контракт API: `GET /api/tracks` принимает `offset` и `sort=relevance`,
  `GET /api/stats` отдаёт `bytes` и `migrations`.
- `packages/shared`: `media()`, `tracksPage()`, `listen()`, `history()`;
  `streamUrl()`/`coverUrl()` удалены — вместо них подписанные ссылки.
- Тестов API стало 14: подписи, Range/416, дедуп, FTS, история, плейлисты,
  метрики и заголовки безопасности.

### Ограничения версии

- Транскодирования всё ещё нет (Фаза 2): отдаётся оригинальный файл.
- `/api/v1` и OpenAPI-схема не сделаны — контракт описан в `docs/API.md`.
- Мобильное и десктопное приложения не пересобирались (нет устройства/Rust в CI).

- `packages/shared` — типы, HTTP-клиент, утилиты (используются web и мобильным клиентом).
- Каркасы: Expo-приложение (вход, библиотека, плеер) и Tauri 2 (глобальные медиа-клавиши,
  CSP, автообновление).
- 9 контрактных тестов API (`npm test`), скрипт демо-наполнения, скрипт бэкапа, Dockerfile, CI.

### Известные ограничения

- Нет транскодирования (нужен ffmpeg): отдаётся оригинальный файл; FLAC не играет в Safari.
- Мобильная и десктопная сборки не проверялись в этом окружении (нет Rust и устройств).
- Обложки: API готов (`PUT /api/tracks/:id/cover`), UI-загрузки пока нет — рисуются заглушки.
- Нет публичных ссылок и шаринга (этап 4).
