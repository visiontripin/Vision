# Changelog

## 0.6.0 — 2026-11-09

Фаза 2 «Аудио 2.0»: лёгкий поток, ровная громкость, HLS и прогрев следующего трека.

### Добавлено

- **Фоновый транскодинг** (`services/api/src/transcode.js`): после загрузки трек
  попадает в очередь и перекодируется в **opus 96 kbps** и **aac 128 kbps**, плюс
  **HLS-нарезка** по 6 секунд. Очередь последовательная, ответ клиенту ffmpeg не ждёт.
- **Нормализация −14 LUFS** (`loudnorm=I=-14:TP=-1.5:LRA=11`) при каждом варианте —
  треки из разных источников звучат на одном уровне.
- **`GET /api/tracks/:id/stream?format=opus|aac`** — отдача варианта с Range; если его
  ещё нет, сервер прозрачно отдаёт оригинал (`X-Variant-Fallback`).
- **HLS**: `GET /api/tracks/:id/hls.m3u8` и `GET /api/tracks/:id/hls/:segment`.
  Сегменты в плейлисте переписаны в абсолютные пути с той же HMAC-подписью, поэтому
  относительное разрешение URL не ломает авторизацию.
- **`GET /api/media`** теперь отдаёт `streams: { original, opus, aac }` и `hls`;
  `GET /api/tracks/:id` — список готовых `variants`.
- **Выбор кодека на клиенте** через `canPlayType()`: opus → aac → оригинал, а в Safari
  с нативным HLS — плейлист.
- **Prefetch следующего трека**: подписанная ссылка запрашивается заранее, первые
  256 КБ уходят в HTTP-кэш браузера — переключение почти без буферизации.
- **320 пиков вместо 180** + сглаживание волны (среднее по окну и 3-точечный фильтр),
  чтобы не было «дребезга» на тихих участках.
- Метрики `vision_transcode_total{result}` и `vision_transcode_seconds_total{kind}`;
  `/api/health` показывает `ffmpeg` и `transcode`.
- `TRANSCODE_BACKFILL=1` — при старте догоняет треки, загруженные до появления ffmpeg.

### Важно

- **Без ffmpeg сервис работает как раньше**: оригиналы, без вариантов и HLS.
  Бинарник ищется в `FFMPEG_PATH` → `ffmpeg-static` → `PATH`; в Docker-образ
  добавлен `apk add ffmpeg`.
- `ffmpeg-static` подключён в `optionalDependencies`: если бинарник не скачался
  (нет сети/неподходящая платформа), `npm install` не падает.
- Осталось на потом: MSE-плеер для HLS в Chrome/Firefox (сейчас HLS играет в Safari),
  gapless/кроссфейд, кэш медиа в Cache Storage.

## 0.5.0 — 2026-11-10

Массовый импорт: папка целиком, ZIP-архив и список ссылок SoundCloud из файла.

### Добавлено

- **Импорт папки** — кнопка «Папка» (`webkitdirectory`) и перетаскивание каталога
  с рекурсивным обходом через `webkitGetAsEntry`.
- **Импорт ZIP без зависимостей** — свой парсер центрального каталога и
  распаковка `deflate` через встроенный `DecompressionStream('deflate-raw')`.
  Служебные файлы (`__MACOSX/`, `._*`, `.DS_Store`), картинки и текст
  отбрасываются; ZIP64 и шифрованные архивы пропускаются, не ломая импорт.
- **Отчёт по очереди**: загружено / дубликатов / ошибок, прогресс по каждому файлу,
  понятный статус «уже в библиотеке» для 409 от API.
- **Импорт списка ссылок SoundCloud** из `.txt`/`.csv` — ссылки вытаскиваются
  регуляркой и уходят пачками по 50.
- Анализ аудио (длительность + пики) вынесен в `apps/web/src/audio.ts` и
  переиспользуется одиночной и массовой загрузкой.
- Разбор имён: «01 - Track.mp3» больше не делает «01» исполнителем, а папка
  «Artist - Album/» из архива подсказывает исполнителя.

### Изменено

- `npm run test:local` теперь гоняет 12 тестов: IndexedDB-клиент (3), разбор имён
  файлов (3), ZIP-парсер и подсказки исполнителя (6).
- `tsconfig` веб-клиента разрешает импорт с расширением `.ts` (нужно тестам).

## 0.4.0 — 2026-11-10

Контент без нарушения прав: полка «Из SoundCloud» (метаданные + официальный
плеер) и расширенная демо-библиотека.

### Добавлено

- **`/api/external`** — закладки на треки SoundCloud: импорт по ссылке через
  официальный oEmbed, allowlist доменов, нормализация ссылки, дедупликация,
  заметки и удаление. Аудио не скачивается, длительность не выдумывается,
  поток не проксируется.
- **Раздел «Из SoundCloud»** в веб-клиенте: вставка ссылок пачкой, карточки,
  встроенный официальный плеер (iframe только с `w.soundcloud.com`),
  ссылка «Открыть», удаление, понятные ошибки по каждой ссылке.
- CSP расширен точечно: `frame-src https://w.soundcloud.com https://soundcloud.com`,
  всё остальное по-прежнему `'self'`.
- **`docs/CONTENT.md`** — политика контента: что можно, что нельзя, почему
  нельзя «просто скачать» с SoundCloud и где брать легальную музыку.
- Демо-набор вырос до 9 треков и 2 плейлистов (`npm run seed`), у треков появились
  описания, добавлены жанры Downtempo и House.

### Изменено

- `packages/shared`: `external()`, `importExternal()`, `updateExternal()`,
  `deleteExternal()`, тип `ExternalTrack`.
- Тестов API стало 18: импорт через поддельный oEmbed (без сети), дедупликация,
  отказ чужим доменам и несуществующим трекам.

## 0.3.0 — 2026-11-10

Завершение Фазы 1: стабильный версионированный контракт и виртуализация списка.

### Добавлено

- **`/api/v1/*`** — версионированный алиас контракта (`/api/*` продолжает работать).
  Внутри маршруты описаны один раз; версия живёт в пути и в `/api/health`.
- **OpenAPI 3.1** — `GET /api/v1/openapi.json` (без токена). Схема лежит рядом с
  кодом (`services/api/src/openapi.js`): все маршруты, схемы Track/Playlist/
  HistoryEntry/Stats/MediaItem/Error, security-схемы bearer + медиа-подпись.
- **Виртуализация списка треков** без зависимостей: при > 120 записях рисуется
  окно ±8 строк, высота строки измеряется по факту (`getBoundingClientRect`),
  `aria-posinset` / `aria-setsize` сохраняют семантику для скринридеров.
  Библиотека на 5 000 треков держит в DOM ~30 узлов вместо 5 000.

### Изменено

- Метрики лейблят маршруты канонически (`/api/v1/tracks` → `/api/tracks`),
  чтобы дашборды не расщеплялись на два ряда.
- Тестов API стало 16 (добавлены схема и v1-алиас).

## 0.2.0 — 2026-11-10

Фаза 1 «Прод-готовность веба»: поиск, метаданные, безопасные медиа-ссылки,
наблюдаемость и «Продолжить слушать».

### Добавлено

- **FTS5-поиск** (`unicode61 remove_diacritics 2`) по названию, артисту, альбому,
  жанру и описанию с префиксным совпадением, сортировками
  (`relevance|recent|oldest|title|plays|duration`), `limit/offset` и `X-Total-Count`.
  Индекс синхронизируется триггерами и в транзакциях правки/удаления.
- **Миграции БД** с таблицей `schema_version`: `001-base`, `002-fulltext-search`,
  `003-checksum` (уникальный частичный индекс), `004-listens`. Идемпотентны,
  применяются при старте, статус виден в `/api/health`.
- **Теги и обложки из файлов** — собственный парсер без зависимостей: ID3v2.3/2.4
  (включая APIC), FLAC Vorbis comments + PICTURE, WAV `LIST/INFO` и `id3 `-чанк,
  Ogg/Opus, MP4 `ilst`, ID3v1 в хвосте. Лимит обложки 5 МБ, ошибки парсинга не
  ломают загрузку.
- **Подписанные медиа-URL**: `GET /api/media?ids=` выдаёт HMAC-SHA256 ссылки на
  поток и обложку с TTL (`MEDIA_URL_TTL_MS`). Токен больше не попадает в URL —
  `?token=` удалён.
- **Дедупликация по SHA-256** при загрузке: `409 duplicate` + существующий трек.
- **История прослушиваний** (`/listen`, `/api/history`) и блок «Продолжить слушать»
  в веб-клиенте: карточки с позицией, запуск с того же места.
- **Наблюдаемость**: `/metrics` в формате Prometheus (счётчики, гистограмма
  задержек, gauge по библиотеке), структурные JSON-логи с `X-Request-Id`,
  security-заголовки и CSP.
- **Надёжность SQLite**: WAL, `synchronous=NORMAL`, `foreign_keys=ON`,
  `busy_timeout=5000`.
- Веб-клиент: поиск через сервер (FTS) с дебаунсом и общим числом результатов,
  размер медиатеки в статистике, мобильный прогресс-бар с перетаскиванием и
  safe-area отступы, кэш подписанных ссылок с фоновым обновлением.

### Изменено

- Контракт API: `GET /api/tracks` принимает `offset` и `sort=relevance`,
  `GET /api/stats` отдаёт `bytes` и `migrations`.
- `packages/shared`: `media()`, `tracksPage()`, `listen()`, `history()`;
  `streamUrl()`/`coverUrl()` удалены — вместо них подписанные ссылки.
- Тестов API стало 14: подписи, Range/416, дедуп, FTS, история, плейлисты,
  метрики и заголовки безопасности.

### Ограничения версии

- Транскодирования всё ещё нет (Фаза 2): отдаётся оригинальный файл.
- `/api/v1` и OpenAPI-схема не сделаны — контракт описан в `docs/API.md`.
- Мобильное и десктопное приложения не пересобирались (нет устройства/Rust в CI).

## 0.1.0 — 2026-11-09

Первый рабочий срез: документация + фундамент продукта.

### Добавлено

- `docs/ROLES.md` — 11 ролей, зоны ответственности, RACI, протокол передачи работы,
  гейты качества и готовые системные промпты для агентов.
- `docs/PRODUCT.md` — scope MVP, non-goals, сценарии, критерии приёмки, NFR.
- `docs/ARCHITECTURE.md`, `docs/API.md`, `docs/ROADMAP.md`, `docs/RUNBOOK.md`, ADR 0001–0005.
- API на Node 22 (`node:http`, `node:sqlite`) без внешних зависимостей:
  вход по паролю (HMAC-токен), загрузка с проверкой magic bytes, стриминг с Range/206,
  обложки с ETag, плейлисты, лайки, статистика, rate limit.
- Web-клиент (React 19 + TS + Vite): библиотека с поиском/фильтрами, drag&drop загрузка
  с расчётом волны в браузере, плеер (очередь, shuffle, повтор, Media Session,
  восстановление сессии), плейлисты, лайки, статистика, адаптивная тёмная тема.
- `packages/shared` — типы, HTTP-клиент, утилиты (используются web и мобильным клиентом).
- Каркасы: Expo-приложение (вход, библиотека, плеер) и Tauri 2 (глобальные медиа-клавиши,
  CSP, автообновление).
- 9 контрактных тестов API (`npm test`), скрипт демо-наполнения, скрипт бэкапа, Dockerfile, CI.

### Известные ограничения

- Нет транскодирования (нужен ffmpeg): отдаётся оригинальный файл; FLAC не играет в Safari.
- Мобильная и десктопная сборки не проверялись в этом окружении (нет Rust и устройств).
- Обложки: API готов (`PUT /api/tracks/:id/cover`), UI-загрузки пока нет — рисуются заглушки.
- Нет публичных ссылок и шаринга (этап 4).
